# 一周制作范围与验收基线

## 1. 项目边界

[CONFIRMED]
- 本轮只有三个世界。
- 两个可玩世界：书桌站、失重花园。
- 一个纯展示世界：云海尽头/最后一站。
- 共享列车空间控制在一节车厢或一个紧凑的公共空间。
- 不制作《梦境邮局》。
- 不扩展第四、第五个世界。
- 不追求完整开放世界。

## 2. 推荐最小交付

### 共享列车
- 一节可辨识的车厢或车厢局部。
- 一个到站/离站连接方式。
- 一张显示三个站点的旅程地图。
- 统一的列车声音标识（若音频能力允许）。

### 世界 01：书桌站
- 一个完整的微缩探索区域。
- 一个明确的物件互动/环境谜题闭环。
- 至少一条可选探索支路。
- 一个能看出书桌尺度的远景。
- 复用已有《桌面以下》资产，但需重新验证导入和质量。

### 世界 02：失重花园
- 一个连续浮空花园区域。
- 一个明显的空间规则展示。
- 至少一次路线发现或移动平台体验。
- 一个中央温室/巨型花朵/观景地标。
- 不实现真实任意方向重力，除非技术探针证明低成本可行。

### 世界 03：云海尽头
- 一个宏大但可读的终点站。
- 列车停靠和下车位置。
- 一条通往观景台的路线。
- 云海、远方世界轮廓和铁路尽头。
- 一段克制的最终演出。
- 不做复杂任务和机关。

## 3. 资源优先级

P0：
- 列车关键外观。
- 三个世界各自的主地标。
- 两个可玩世界的主要路线和互动。
- 站点之间可工作的连接。
- 角色出生点、出口和安全回退。
- 场景保存与重新打开验证。

P1：
- 环境细节和装饰。
- 音乐、环境声、汽笛和交互音效。
- 旅程地图和纪念物陈列。
- 少量环境叙事线索。

P2：
- 复杂 NPC。
- 多个支线任务。
- 多套收藏系统。
- 复杂天气、动态水体和高成本特效。
- 真实列车驾驶和长距离物理移动。

## 4. 七天节奏建议

| 日程 | 核心目标 | 验收物 |
|---|---|---|
| Day 1 | 编辑器能力验证、项目结构和世界白盒 | 可运行的最小场景、风险清单 |
| Day 2 | 三世界空间骨架和入口/出口 | 三个世界可预览 |
| Day 3 | 两个可玩世界完成核心交互 | 两个玩法闭环 |
| Day 4 | 核心资产、材质、灯光和构图 | 远/中/近景截图 |
| Day 5 | 列车连接、音频和环境反馈 | 完整旅程串联 |
| Day 6 | 无提示试玩、问题修复、性能优化 | 试玩记录和候选版本 |
| Day 7 | 最终检查、录屏、备份和发布准备 | 可体验版本和交付记录 |

## 5. 统一验收标准

### 体验
- 玩家知道如何进入第一个世界。
- 两个可玩世界的核心玩法有明显差异。
- 每个世界有明确目标或探索终点。
- 站点切换不会让玩家迷失。
- 纯展示世界有值得抵达的观景位置。

### 美术
- 三个世界在第一眼就能区分。
- 列车在三个世界中保持一致的识别特征。
- 核心资产没有明显破面、穿插、材质错误或比例失衡。
- 远/中/近景均通过检查。
- 不靠后期特效掩盖模型质量。

### 技术
- 场景可以保存并重新打开。
- 入口、出口和传送/切换逻辑可重复使用。
- 没有严重碰撞、卡死或无法恢复的位置。
- 资源容量符合编辑器当前版本限制。
- 实际预览/发布环境没有严重丢失资产。

### 交付证据
- 每个世界的实际编辑器截图。
- 每个世界至少一段真实运行录屏。
- 完整旅程录屏。
- 资产清单与授权记录。
- 已知问题和降级说明。

## 6. 一周冲刺的取舍原则

当时间不足时，按以下顺序砍内容：
1. 先砍普通装饰数量。
2. 再砍 NPC 和支线。
3. 再砍复杂演出。
4. 保留核心玩法闭环、世界地标、列车连接和终点观景。
5. 宁可一个区域精致、另外区域范围收敛，也不要三个世界都做成粗糙大地图。
