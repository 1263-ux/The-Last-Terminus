# Agent Execution Protocol｜Agent 执行协议

## 1. 适用对象

- 成员 A 使用的 Claude/GPT Agent。
- 成员 B/C 使用的 DSH Agent。
- 参与模型研究、素材筛选、文档生产的辅助 Agent。

所有 Agent 均遵循同一生产规则。模型能力不同，不改变项目的设计基线和验收要求。

## 2. 任务启动前：先理解，不要立即操作

收到任务后，必须依次完成：

1. 阅读根目录 `AGENTS.md`。
2. 阅读任务包指定的设计文档和参考资料。
3. 检查任务所需的项目、场景、资产和当前分支状态。
4. 用自己的话复述目标、范围、交付物和验收标准。
5. 列出依赖、风险、编辑器能力假设和需要先验证的项目。
6. 输出短执行计划，等待任务包要求的批准点。

禁止只根据一句自然语言指令就开始批量生成模型、地形或场景。

## 3. 计划必须具体

计划至少回答：
- 本次唯一目标是什么？
- 哪些文件/场景/资产会被修改？
- 哪些内容明确不做？
- 依赖哪些 GLB、WPRE、贴图、音频或公共模块？
- 造世界编辑器中需要进行哪些操作？
- 哪些能力已经验证，哪些仍是假设？
- 如何证明任务完成？
- 如果关键功能不支持，最低成本降级是什么？

如果任务存在多个重大未知，先做最小技术探针，不要把未知隐藏在大规模制作里。

## 4. 编辑器操作纪律

1. 操作前确认当前打开的项目和场景，避免改错工程。
2. 重要操作前后保存；大改动前建立可恢复版本或备份。
3. 每次只处理一个清晰的子目标，完成后检查实际视口结果。
4. 资产导入后检查尺寸、朝向、材质、贴图、碰撞、层级和依赖。
5. WPRE/场景包导入后检查对象层级、相对位置、资源引用和交互是否保留。
6. 不确定按钮、参数或功能含义时，先查看官方文档或做可撤销的小测试，不要盲目点击。
7. 不通过连续随机提示词生成来替代明确的设计判断。
8. 不因一次生成失败就重复消耗大量 AI 额度；先检查提示词、参考图、范围和参数。
9. 不覆盖其他成员拥有的场景或文件。
10. 任何可能破坏项目、批量替换资源或改变公共配置的操作，必须先备份并说明。

## 5. Vibe Workflow 的约束

Agent 可以主动规划和操作，但必须遵循：

- **小步执行：** 每个子任务完成后检查，不一次性做完整个世界。
- **证据优先：** 真实视口、预览和运行结果优先于 Agent 自述。
- **禁止脑补：** 不知道编辑器是否支持的功能必须标为 TO-VERIFY。
- **不扩大范围：** 不自行增加 NPC、任务、建筑群、玩法系统或剧情。
- **先复用：** 先搜索项目现有资产和编辑器官方资产，再决定是否新建。
- **变更透明：** 修改任务目标、场景结构、公共接口前先提交变更提案。
- **可恢复：** 关键阶段保留备份、Git 提交或可回滚版本。

## 6. 停止并升级给总设计师/A 的条件

遇到以下情况，不得自行做重大决定：

- 现有设计无法在编辑器中实现。
- 需要改变核心玩法或世界空间结构。
- 关键资产无法导入或导入后严重损坏。
- WPRE 交接丢失层级、材质、交互或引用。
- 需要更换核心资产、主地标或视觉方向。
- 需要扩大场景/项目范围。
- 可能覆盖其他成员的工作。
- 预计任务将超过约定工时或阻塞其他世界。

汇报必须包含：问题证据、已尝试步骤、影响范围、至少一个降级方案、推荐方案。

## 7. Review 节点

除非任务包另有约定，每个世界至少经历：

1. **Design Review：** 设计卡、参考图、路线和玩法闭环批准。
2. **Whitebox Review：** 空间关系、玩家路线、入口出口和交互位置批准。
3. **Art Review：** 核心模型、材质、光照、构图和资产密度检查。
4. **Playable Review：** 实际运行、操作、碰撞、反馈和性能检查。
5. **Handoff Review：** 交付文件、依赖、版本和重新打开测试。

未通过前一阶段，不应大规模投入后一阶段。

## 8. 每次汇报格式

- 任务 ID / 负责人 / 当前版本
- 本轮目标
- 已完成内容
- 修改过的文件、场景和资产
- 真实截图/录屏/预览证据
- 验收标准逐项状态：PASS / FAIL / NOT TESTED
- 编辑器能力验证结果
- 当前问题和风险
- 下一步计划
- 是否需要总设计师或 A 决策

禁止只回复“完成了”“已经优化”“效果很好”而不提供证据。
