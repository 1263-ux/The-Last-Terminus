# Integration Contract｜Git、资产与世界集成约定

## 1. 目标

让 A、B、C 能够并行制作，同时保证成果可以被 A 接收、重新打开、检查并集成。Git 是版本管理和协作主渠道；GLB/WPRE 是已确认可导入的资产交换格式。它们各自解决不同问题。

## 2. 当前已知与待验证边界

### 已知
- 团队使用新版抖音「造世界 AI 编辑器」本地 PC 工作流。
- 团队确认编辑器支持导入 GLB 和 WPRE。
- 团队计划使用 Git 协作。
- 三个成员均可操作编辑器。

### 必须实测，不得假定
- 造世界项目完整目录是否可在不同电脑无损复制。
- 项目配置、缓存、用户数据和可再生成文件分别是什么。
- 场景文件是否为二进制，以及是否支持文本差异/合并。
- WPRE 是否保留完整对象层级、材质、贴图、碰撞、交互、脚本或外部引用。
- GLB 导入是否保留材质、动画、透明度、贴图和碰撞（逐项测试）。
- 不同编辑器版本之间是否兼容。
- 同一工程多人同时打开/修改是否安全。
- 跨项目导入后，资源 GUID/引用是否稳定。

在以上问题有实测结论前，禁止宣称“场景可以自动合并”或“WPRE 包含完整工程”。

## 3. Git 协作规则

### 分支
- `main`：可打开、可运行的稳定集成版本。
- `feature/train-core`：A 的公共列车和集成开发。
- `feature/desk-world`：B 的书桌站开发。
- `feature/floating-garden`：C 的失重花园开发。

如使用个人分支，命名为 `feature/<owner>-<task-id>`，合并前回到对应世界分支或由 A 集成。

### 提交
- 每个可验证里程碑提交一次。
- 提交信息说明任务 ID 和实际变更，例如 `feat(desk): B-04 add ruler bridge interaction`。
- 不提交缓存、临时下载、无关导出、个人设置和凭证。
- 不随意重命名/移动编辑器内部资源；先验证引用是否会失效。
- 不在未检查状态下使用 force push、reset --hard 或批量覆盖。

### 二进制冲突
GLB、WPRE、贴图、音频、场景二进制文件通常不适合 Git 文本合并。
- 同一二进制文件只允许一个主要写入者。
- 冲突时由文件所有者确定保留版本，不能自动拼接。
- Git LFS 是否启用，根据实际文件大小、仓库配额和团队环境决定；启用前先验证成员均已安装并配置。
- 保留源文件和可恢复版本，避免只剩压缩后的交付件。

## 4. 目录约定（逻辑结构，最终按编辑器真实工程结构映射）

├── worlds/

## 5. GLB 资产交接规范

每个 GLB 交付至少包含：
- 原始文件和版本号。
- 资产名称、用途、所属世界。
- 单位/尺寸、朝向、原点说明。
- 材质和贴图依赖。
- 是否包含动画。
- 是否需要碰撞体。
- 面数/贴图尺寸（能取得时记录）。
- 来源、作者和许可证。
- 导入后编辑器截图。

导入检查：
1. 尺寸与世界比例正确。
2. 朝向、原点和旋转正确。
3. 贴图引用完整。
4. Base Color、Normal、透明度等实际效果正确。
5. 动画（如有）播放正常。
6. 碰撞/可交互属性符合预期。
7. 在目标视距和光照下视觉成立。

## 6. WPRE 资产交接规范

WPRE 作为编辑器支持的资产格式使用，但在完成验证前，不假定它是完整场景、项目或 Prefab 的等价物。

每次交接需附：
- WPRE 文件及版本。
- 创建编辑器版本。
- 导出/生成方式。
- 依赖资源清单。
- 预期层级结构截图。
- 导入后的层级结构截图。
- 材质、贴图、碰撞、交互和动画检查结果。
- 不能随包携带的外部依赖说明。

如果导入后缺少任何关键配置，补交依赖资产或改用经过验证的交付方式。

## 7. World Package 最低交付结构

每个世界交付时，至少有：
- `WORLD-CARD.md`：世界目标、体验、空间规则和范围。
- `ASSET-MANIFEST.csv`：全部资产及依赖。
- `SCENE-STRUCTURE.md`：场景层级和关键对象说明。
- `INTERACTION-FLOW.md`：交互逻辑、触发条件和反馈。
- `ENTRY-EXIT.md`：出生点、出口和集成接口。
- `KNOWN-ISSUES.md`：未解决问题和降级项。
- 项目/场景/WPRE/GLB 实际交付文件。
- 远景、中景、近景截图。
- 完整玩法录屏。

## 8. 集成顺序

1. A 创建稳定的集成基线和公共接口。
2. B/C 在各自分支/独立副本中开发。
3. B/C 每日提交可集成快照，不等最终完成。
4. A 在集成副本导入世界包，检查依赖、层级和引用。
5. A 将集成结果提交到 `main` 或集成分支。
6. 原世界负责人在集成环境验证其场景没有偏移或丢失。
7. 总设计师进行完整旅程 Review。

## 9. 集成失败的降级顺序

若完整场景无法跨项目交接：
1. 尝试 WPRE 导出/导入并记录丢失项。
2. 尝试 GLB 组合资产交付，交互在主工程中重新配置。
3. 将世界拆成可独立导入的场景模块。
4. 最低限度由 A 在主项目中重组资产和交互。

不要等到最终阶段才发现无法合并。第一天必须做跨成员迁移实验。
