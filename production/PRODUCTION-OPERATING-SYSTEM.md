# Production Operating System｜一周冲刺生产操作系统

> 原则：方向明确、边界清楚、参考充分、结果开放、验证严格。

## 1. 生产哲学

任务包定义玩家体验、世界概念、视觉识别、成熟参考、范围边界、质量底线和验收结果；Agent 自主决定具体模块拆分、提示词、资产组合、编辑器操作和低成本实现方式。

**约束结果与质量，不约束每一步思考。**

标准循环：理解目标 → 研究参考 → 提出方案 → 快速原型 → Review → 正式生产 → 实际验证 → 交付复盘。

## 2. 团队角色与决策权

### 总设计师 / Creative Director
- 维护 World Bible、整体体验、美术和玩法方向。
- 负责关键 Tripo 模型生成与取舍。
- 审核视觉方案、玩法原型、音乐候选和阶段成果。
- 对世界观、范围、玩法职责和关键视觉方向拥有最终决定权。
- 不操作造世界编辑器；通过截图、录屏、预览和试玩控制质量。

### A / Train & Integration Lead
- 验证本地项目、Git、GLB/WPRE 交接和恢复。
- 负责列车 Hub、旅程地图、世界入口/出口和集成。
- 制作云海尽头纯展示世界。
- 接入统一音乐/环境音，负责最终完整旅程版本。

### B / Desk World Lead
- 负责书桌站资产审计、白盒、空间、玩法、场景生产和交付。
- 提交关键模型需求卡与提示词草案；总设计师负责 Tripo 生成。
- 负责 Blender 检查、导入、适配、玩法验证。

### C / Floating Garden Lead
- 负责失重花园空间、AI 地形、玩法、场景生产和交付。
- 提交关键模型需求卡与提示词草案；总设计师负责 Tripo 生成。
- 负责 Blender 检查、导入、适配、玩法验证。

### 决策规则
- 设计方向：总设计师批准。
- 技术实现：对应 Owner 实测；A 判断集成影响；总设计师判断是否满足体验目标。
- 每个场景/二进制文件只有一个主要写入者。
- Agent 可以提出替代方案，但不得悄悄改变已确认决策。

## 3. Agent 小团队：按需组建，不固定人数

每个成员设一个主控 Agent。主控按阶段动态拆分，不机械启动全部角色。

| 能力角色 | 责任 | 典型产物 |
|---|---|---|
| Orchestrator / Producer | 目标理解、任务拆分、依赖和进度 | 计划、任务板 |
| Reference Researcher | 成熟项目、官方资料、视觉/玩法案例 | 参考板、设计观察 |
| World / Level Designer | 空间拓扑、路线、地标、节奏 | 白盒方案、路线图 |
| Art / Asset Analyst | 视觉语言、模块拆分、模型需求 | Art Direction、Asset Cards |
| Editor Operator | 实际编辑器操作、保存、导入、预览 | 可运行场景、录屏 |
| QA / Red Team | 独立找偏差、玩法漏洞、技术假设 | 缺陷清单、验收结果 |
| Audio Researcher | 音乐/音效搜索、试听、授权核验 | Audio shortlist |

A：Claude 主控，GPT 或独立上下文做 Red Team；A 本人操作编辑器。B/C：DSH 主控，按需启动研究、空间、资产、玩法、执行和 QA 子 Agent；成员本人操作编辑器。

### 并行与串行
可并行：参考研究、现有资产审计、不同视觉方案、互不写入同一文件的模块分析、独立 QA。
必须串行：方向批准 → 关键 Tripo 生成 → 导入验收；白盒通过 → 精细美术；公共接口确认 → 集成；Gate 通过 → 下一阶段。
禁止多个 Agent 同时写同一场景/二进制文件。

## 5. 七天里程碑与交付闭环

### Day 1｜方向理解与技术风险暴露
A：项目保存/恢复、Git、GLB/WPRE、世界连接最小探针；列车 Hub 灰盒。
B：现有桌面以下资产审计；书桌站空间和玩法方案。
C：失重花园空间方案；AI 地形、移动平台/机关最小探针。
总设计师：统一设计卡、视觉方向、关键 Tripo 需求评审。
20:00 交付：三份设计卡、参考摘要、A 的技术探针报告、B/C 白盒草案、P0 风险清单。
Gate D1：三人能准确复述项目；两种玩法明显不同；关键未知已暴露。未通过不批量生成模型。

### Day 2｜白盒与空间路线
A：列车 Hub、终点站和站点接口白盒。
B：书谷、尺子桥、铅笔盒小镇局部白盒。
C：入口浮岛、主路径、温室目标和观景点白盒。
总设计师：玩家视角、远中近景和主路线 Review；批准 P0 资产需求。
20:00 交付：三个可预览白盒、路线图、入口到目标录屏、关键视线截图、Tripo 需求清单。
Gate D2：目标可见、路线可读、空间可走通；未通过先修白盒，不做精细模型。

### Day 3｜玩法闭环
A：验证站点连接/返回。
B：尺子桥交互可运行，测试主解法和替代/降级方案。
C：空间路线发现可运行，完成一次“原来这里能走”的发现。
总设计师：根据真实录屏/试玩判断玩法是否成立。
20:00 交付：两个完整玩法录屏、状态变化前后截图、失败恢复测试、试玩观察。
Gate D3：玩家知道做什么、为什么做、成功后发生什么；不能只是静态装饰或自动动画。

### Day 4｜关键美术与声音样板
总设计师：按批准的 Asset Cards 生成关键 Tripo 模型。
A/B/C：Blender 检查、导入、比例/材质/碰撞验证，场景精修。
音频研究：每个场景 2–3 个音乐/环境音候选，实际试听并核验许可。
20:00 交付：关键模型在编辑器内真实显示、远中近景对照、材质问题记录、音频 shortlist。
Gate D4：关键地标有辨识度，模型无严重缺陷，音乐方向匹配；非关键装饰可延后。

### Day 5｜完整串接
A：集成 B/C 世界，完成入口/出口、过场、路线图和声音。
B/C：在集成版本中验证各自世界，修复导入问题。
总设计师：完整旅程 Review。
20:00 交付：可从头到尾体验的集成版本、完整录屏、P0/P1 缺陷清单、稳定 Commit。
Gate D5：三个世界按正确顺序进入、离开和继续，无阻塞性资源丢失/软锁。

### Day 6｜盲测与修复
至少邀请两名未参与制作的试玩者（若可用），不做口头引导。记录卡点、误解目标、无聊段落、眩晕/碰撞、音量问题。
20:00 交付：试玩记录、P0/P1 修复证据、候选版本、已知问题清单。
Gate D6：无 P0 阻塞，核心体验可独立完成。

### Day 7｜最终验收
A：最终集成、备份、发布检查。B/C：验证最终版本场景完整。总设计师：完整旅程试玩。
交付：可重新打开的项目/资产包、稳定 Commit、完整录屏、三世界展示截图、资产/授权清单、已知限制和复盘。
Gate D7：以实际可体验版本验收，不以文档数量或任务完成率验收。

## 6. Gate 验收机制

状态：
- APPROVE：达到阶段目标，进入下一阶段。
- REVISE：方向正确，修复后复审。
- REJECT：核心体验或方向错误，回到方案/白盒。
- BLOCKED：工具/资产/依赖阻塞，提交证据和降级方案。

每项 0–3 分：0 不存在/不能体验；1 有雏形但不清楚或不稳定；2 达到阶段目标；3 明确、稳定、有记忆点。

维度：方向一致性、空间可读性、玩法/展示体验、视觉品质、技术稳定/可恢复性、证据完整性。
通过规则：P0 项不得为 0；核心玩法/入口出口不得为 1；总分至少 12/18。视觉 Gate 的视觉品质至少 2；最终 Gate 每项至少 2。

## 7. 缺陷等级
- P0：无法进入/离开、核心玩法无法完成、工程不可恢复、严重资源丢失、玩家软锁。
- P1：主路线不清、明显碰撞/穿模、核心模型严重破损、关键地标不可见、音频明显异常。
- P2：普通装饰、次要细节、非关键动画和可选支路。

## 8. 每日交付格式
每人 20:00 前提交：今日目标/实际完成、场景与资产版本/Commit、远中近景截图、真实运行录屏、PASS/FAIL/NOT TESTED、最大问题、次日目标、需要总设计师决策的事项。

## 9. 方向变更
玩法与世界职责重复、视觉明显偏离、关键编辑器功能不可用、资产无法导入、影响集成或超出一周范围时，必须暂停并提交 Change Proposal：问题证据、影响、方案 A/B、推荐方案、成本和对里程碑影响。
