# Team Roles｜团队角色与责任边界

## 1. 组织原则

采用「一个总设计控制面 + 三个生产负责人」：

- 总设计师决定做什么、为什么做、做到什么质量。
- A/B/C 分别对公共模块、书桌站、失重花园的实际交付负责。
- Agent 是执行工具，不拥有产品方向决策权。
- 每个场景、项目文件和资产包必须有唯一主要负责人。
- 设计、生产、Review、集成持续进行，不等到最后一天才合并。

## 2. 总设计师 / Creative Director

**工具条件：** 不使用造世界编辑器；通过 GitHub 文档、截图、录屏、预览和试玩结果进行设计控制。

### 持续职责
1. 维护统一 World Bible 和核心设定。
2. 完成列车核心设定。
3. 完成三个世界设计卡。
4. 输出每站视觉参考板和明确的视觉目标。
5. 设计两个可玩世界的核心玩法与完整闭环。
6. 使用 Agent 生成建模需求、资产规格和模型提示词。
7. 筛选三站音乐、环境音和列车声音标识。
8. 每日进行设计 Review，记录决策和返工要求。
9. 最终验收完整旅程。

### 决策权限
- 对世界观、玩法方向、视觉目标、内容范围和验收结果拥有最终设计决定权。
- 可以批准、要求修改或拒绝设计成果。
- 不直接替成员决定未经验证的编辑器技术实现；技术实现由 A 提出证据和方案，总设计师确认其是否符合体验目标。
- 任何会改变已确认设定或三个世界职责的改动，必须先提交变更提案。

### 不承担
- 不负责操作编辑器。
- 不直接维护成员的场景文件。
- 不代替成员完成资产导入和工程调试。
- 不承担无边界的即时反馈；统一通过 Review 记录给出决策。

## 3. 成员 A / Train & Integration Lead

**工具条件：** Claude、GPT、新版造世界 AI 编辑器。

### 主要职责
1. 验证本地项目复制、Git 协作、GLB/WPRE 交接和恢复流程。
2. 建立公共列车车厢与列车视觉识别。
3. 建立站点路线图/旅程地图。
4. 定义并实现三个世界的入口、出口和连接方式。
5. 制作云海尽头纯展示世界。
6. 接入统一音乐、环境音和列车声音。
7. 持续集成 B/C 的世界成果，负责最终集成和发布检查。

### 工作量约束
- A 的首要责任是公共接口、项目稳定性和集成，不是追求终点站资产数量。
- 云海尽头按「一个列车停靠区 + 一个主地标 + 一条观景路线 + 云海远景」控制范围。
- 优先使用经过许可核验的成熟资产和编辑器现有能力。
- 不为真实列车驾驶、复杂载具物理或大型 NPC 系统投入首轮时间，除非技术验证证明低成本且不会影响集成。

### 权限
- 可以决定公共工程组织、分支合并顺序和技术降级方案。
- 不得擅自改变 B/C 的世界核心玩法或视觉方向。
- 对合并冲突和文件格式风险有权暂停集成并要求提交方修复。

## 4. 成员 B / Desk World Lead

**工具条件：** DSH、新版造世界 AI 编辑器；可使用 Tripo、Blender 等外部工具处理资产。

### 主要职责
1. 整理现有 GLB/WPRE 资产，记录来源、版本、依赖和质量。
2. 确定书桌站本轮地图布局，并提交白盒供 Review。
3. 用 Tripo 等工具补充缺失的核心模型。
4. 使用 Blender 检查、修复、优化和组装模型。
5. 在造世界编辑器中搭建场景。
6. 实现尺子桥谜题的可玩闭环。
7. 完成一条隐藏路线和至少一个可观察的环境反馈。
8. 提交可重新打开的世界成果、资产清单和运行证据。

### 范围约束
- 优先复用已有合格资产，不因流程习惯而全部重做。
- 先完成书谷 + 尺子桥 + 铅笔盒小镇局部。
- 杯岸港口等其余区域可作为远景提示，不扩展成完整子地图。
- 不把基地完整成长系统、居民生态和大量支线放入一周首版。

## 5. 成员 C / Floating Garden Lead

**工具条件：** DSH、新版造世界 AI 编辑器；可使用 Tripo、Blender 等外部工具处理资产。

### 主要职责
1. 确定失重花园空间布局，提交白盒供 Review。
2. 使用 AI 地形生成建立基础浮空空间。
3. 使用 Tripo 等工具制作核心花朵、温室和关键建筑资产。
4. 使用 Blender 检查、修复、优化和组装模型。
5. 在造世界编辑器中搭建三层空间。
6. 实现移动平台或经过验证的空间机关。
7. 完成温室地标和高处观景点。
8. 提交可重新打开的世界成果、资产清单和运行证据。

### 范围约束
- 三层必须形成可读、可走通的空间关系，不以悬浮模型堆叠代替关卡。
- 先验证移动平台/机关，再扩大地形和美术制作。
- 不依赖真实任意方向重力；优先通过错层平台、倒置建筑、视线遮挡和预设连接实现空间错觉。
- 只做一个连续的花园区域，不扩展成多座大型浮岛群。

## 6. 责任矩阵

| 工作 | 总设计师 | A | B | C |
|---|---|---|---|---|
| World Bible / 核心概念 | A/R | C | C | C |
| 列车设计 | A/R | R | C | C |
| 公共项目/Git/WPRE 验证 | C | A/R | C | C |
| 书桌站设计与制作 | A（设计批准） | C | R | C |
| 失重花园设计与制作 | A（设计批准） | C | C | R |
| 云海尽头制作 | A（设计批准） | R | C | C |
| 站点连接与集成 | C | A/R | C | C |
| 音乐与声音方向 | A/R | R（接入） | C | C |
| 最终体验验收 | A/R | R（修复） | R（修复） | R（修复） |

说明：A/R = 最终负责并执行；R = 执行负责；C = 需要协作/提供意见。设计批准权始终属于总设计师。

## 7. 共同要求

所有成员都必须：
- 先读根目录 `AGENTS.md` 和对应任务包。
- 先白盒验证，再制作高精资产。
- 不擅自改变已确认设计。
- 不把 AI 概念图当生产模型。
- 不将未经核验的资产放入正式版本。
- 每日提交真实截图/录屏、变更清单、问题和下一步计划。
