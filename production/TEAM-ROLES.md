# Team Roles｜团队角色与责任边界

## 1. 组织原则

采用「一个总设计控制面 + 三个生产负责人」：

- 总设计师决定产品方向、体验目标、关键视觉方向和质量标准。
- A/B/C 分别对公共模块、书桌站、失重花园的实际交付负责。
- Agent 是探索、规划和生产工具，不拥有产品方向的最终决策权。
- 每个场景、项目文件和资产包必须有唯一主要负责人。
- 任务包定义目标和边界，不把每个实现细节提前写死。

## 2. 总设计师 / Creative Director

**工具条件：** 通过 GitHub、参考图、截图、录屏、预览和试玩结果进行设计控制，不操作新版造世界编辑器。

### 主要职责
1. 维护统一 World Bible 和核心设定。
2. 负责列车与三个世界的总体设计方向。
3. 给出美术参考、成熟项目研究方向和视觉质量标准。
4. 规划核心玩法、旅程节奏和声音设计方向。
5. 负责关键 Tripo 模型生成；Agent 根据需求提出资产方案、参考图和提示词。
6. 组织设计 Review，决定接受、修改或放弃哪些方案。
7. 最终验收完整旅程。

### 决策权限
- 对世界观、玩法方向、视觉目标、内容范围和验收结果拥有最终决定权。
- 可以批准、要求修改或拒绝设计成果。
- 不替成员决定未经验证的编辑器技术实现；A 提出证据和方案，总设计师判断其是否符合体验目标。

### Tripo 责任边界
- **总设计师负责实际 Tripo 生成与关键模型选择。**
- A/B/C 负责发现资产需求、提交可选设计方向、尺寸比例参照、结构建议、参考视图和模型提示词草案。
- 总设计师可以自行修改或重写提示词并生成模型。
- 模型交付后，由对应世界 Owner 负责 Blender 检查、导入、场景适配和反馈。
- 普通资产优先复用造世界官方资产库或已有成熟资源，不必所有物件都经过 Tripo。

## 3. 成员 A / Train & Integration Lead

**工具：** Claude、GPT、新版造世界 AI 编辑器。

负责公共列车空间、旅程地图、世界入口出口、云海尽头、音频接入和最终集成。A 的首要责任是公共接口、项目稳定性和集成，不是无限扩大终点站规模。

## 4. 成员 B / Desk World Lead

**工具：** DSH、新版造世界 AI 编辑器、Blender；关键 Tripo 模型由总设计师生成。

负责书桌站空间设计、已有资产审计、核心物件玩法、场景生产、导入验收和交付。

## 5. 成员 C / Floating Garden Lead

**工具：** DSH、新版造世界 AI 编辑器、Blender；关键 Tripo 模型由总设计师生成。

负责失重花园空间设计、地形探索、路线发现玩法、场景生产、导入验收和交付。

## 6. 决策与协作矩阵

| 工作 | 总设计师 | A | B | C |
|---|---|---|---|---|
| World Bible / 核心方向 | A/R | C | C | C |
| 关键视觉方向与 Tripo 生成 | A/R | C | C | C |
| 项目/Git/GLB/WPRE 验证 | C | A/R | C | C |
| 列车与云海尽头 | A（设计决策） | R | C | C |
| 书桌站 | A（设计决策） | C | R | C |
| 失重花园 | A（设计决策） | C | C | R |
| 世界连接与集成 | C | A/R | C | C |
| 音乐与声音方向 | A/R | R（接入） | C | C |
| 最终体验验收 | A/R | R（修复） | R（修复） | R（修复） |

A/R = 最终负责并执行；R = 执行负责；C = 协作/提供意见。

## 7. 共同原则

- 优先复用成熟资产和能力。
- Agent 可以提出替代方案，不必机械照抄任务包示例。
- 核心设定、世界职责和关键视觉方向不能擅自改变。
- 每次阶段 Review 提交真实编辑器截图、录屏或可重新打开的项目。
- 遇到未知能力先做小实验；遇到低成本更优方案，可以提出并快速比较。
