# DAY 03｜核心玩法闭环

## 本阶段目标
让两个可玩世界都出现可操作、可完成、可验证的玩法，而不是静态场景展示。

## A｜列车与集成
- 验证列车 Hub → 书桌站 → 返回/继续的真实连接方式。
- 验证列车 Hub → 失重花园 → 返回/继续的真实连接方式。
- 如果跨场景切换不可用，选择最稳定的同场景分区/传送/遮挡过场降级。
- 继续终点站的漫游路线，但不添加无必要机关。

交付：连接测试录屏、返回流程、失败恢复方式、接口更新。

## B｜书桌站
实现尺子桥核心闭环：
- 玩家看见目标和阻隔。
- 玩家观察尺子/支点/其他物件。
- 玩家做出操作或选择。
- 环境通路发生可见变化。
- 玩家实际走过新路线。
- 成功有环境反馈，错误操作可恢复。
尽可能测试一个替代解法；如果自由物理不稳定，研究吸附点/预设状态/组合资产等实现。

交付：从进入到完成的完整录屏、状态变化前后截图、主/替代方案测试、失败恢复记录。

## C｜失重花园
实现路线发现闭环：
- 玩家先看见温室/巨花目标。
- 直接路径不成立。
- 玩家观察根系、平台、花朵或空间结构。
- 发现另一条合理路径。
- 通过连接结构抵达目标。
- 抵达后获得新视野。
移动平台不稳定时，采用固定平台或触发式替代方案，不让技术问题拖垮核心玩法。

交付：完整玩法录屏、路线发现前后对比、平台/机关测试、失败恢复记录。

## 跨团队协作
- B/C 向 A 提供能进入的临时世界快照和出口位置，不必等待美术完成。
- A 用临时版本做一次串接验证，并把问题回传。
- B/C 互相试玩对方白盒，重点判断两种玩法是否重复。
- 独立 QA 不接受作者口头讲解，尽量只看录屏或实际试玩。

## Gate D3
通过条件：
- 书桌站确实改变了物件/通路。
- 失重花园确实发生了空间路线发现。
- 两者玩法差异明显。
- 入口、出口和失败恢复可复现。

未通过：保留最小可玩版本，删除不稳定的复杂机制，继续修复闭环。
