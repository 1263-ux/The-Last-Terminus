# Phase Prompts｜阶段提示词系统

## 1. 为什么不使用一条永久主提示词

A/B/C 的长期角色和责任已经写在任务包中。实际执行时，**每个阶段只加载当前阶段提示词**，避免一条超长提示词长期约束 Agent，导致上下文膨胀和执行僵化。

- `ROLE-A-TRAIN-INTEGRATION.md` / `ROLE-B-DESK-WORLD.md` / `ROLE-C-FLOATING-GARDEN.md`：三份成员专属启动提示词，包含 Git 初始化、角色职责、动态 Agent 团队、跨团队协作和 Day 1 启动。
- `00-BOOTSTRAP.md`：如果只想单独初始化仓库、不立即开始 Day 1，可以使用这份通用初始化提示词。
- `DAY-01` 至 `DAY-07`：每个阶段一份短期执行指令。
- 任务包：提供持续有效的世界目标、设计边界、参考和验收基线。
- 当前阶段提示词：规定本轮重点、协作、交付和停止条件。

## 2. 三份成员专属提示词

- [A｜列车与集成（Claude 主控 + GPT 独立审查）](ROLE-A-TRAIN-INTEGRATION.md)
- [B｜书桌站《桌面以下》（DSH 主控）](ROLE-B-DESK-WORLD.md)
- [C｜失重花园（DSH 主控）](ROLE-C-FLOATING-GARDEN.md)

推荐：每位成员直接发送自己对应的 ROLE Prompt。它会先初始化仓库/分支、阅读任务包、组建当前最小 Agent 团队并启动 Day 1。不要三份都发给同一个 Agent。

## 3. 使用顺序

| 文件 | 何时使用 | 目的 |
|---|---|---|
| `00-BOOTSTRAP` | 第一次接手 | 初始化仓库和专属分支 |
| `DAY-01` | 首轮 | 理解、研究、资产审计、技术探针 |
| `DAY-02` | D1 Gate 后 | 白盒、空间路线、入口出口 |
| `DAY-03` | D2 Gate 后 | 两个可玩世界的玩法闭环 |
| `DAY-04` | D3 Gate 后 | Tripo 关键模型、Blender、声音样板 |
| `DAY-05` | D4 Gate 后 | 跨世界集成和完整旅程 |
| `DAY-06` | D5 Gate 后 | 盲测、缺陷修复和范围收敛 |
| `DAY-07` | D6 Gate 后 | 最终验收、稳定版本和交付 |

阶段提示词不是“日历到了就强制跳转”。若 Gate 未通过，继续使用当前阶段的 REVISE 任务；可以同时推进不依赖阻塞项的其他工作。

## 4. 每个阶段的通用执行协议

1. 先检查当前 Git 分支、工作区和最新 main；保护未提交工作。
2. 读取项目基线、自己任务包和当前阶段提示词。
3. 主控按需组织 Agent，不机械启动固定数量。
4. 明确本阶段的目标、输入、可并行工作、文件 Owner 和验收证据。
5. 先做最小可验证成果，再决定是否扩大投入。
6. 阻塞局部化：建议 20–30 分钟最小验证；无法解决则记录证据、提出降级方案、发出依赖请求，并继续其他独立工作。
7. 不得伪造完成状态；占位资产、临时接口、降级方案必须明确标注。
8. 阶段结束提交真实截图、录屏、可重开工程/资产、Git Commit 和问题清单。
9. 阶段 Gate 由总设计师/指定 Review 角色决定。Agent 自检不等于 Gate 通过。

## 5. 三团队协作协议

- A 是公共接口和集成协调人；尽早发布玩家尺度、Entry/Exit、资源交接要求和连接测试结果。
- B/C 尽早向 A 提交 Entry/Exit Anchor、出生朝向、安全落脚区和临时世界快照，不等完整世界制作完成。
- B/C 互相分享编辑器技巧、资产处理经验和玩法可读性 Review，但不互相覆盖对方场景。
- 每个成员只写自己的世界目录和报告目录；公共接口文档由 A 维护，设计基线由总设计师维护。
- 每个阶段至少交换一次可复用成果。通过团队群/PR/Commit 链接传递，不要求对方必须等 PR 合并才开始研究。
- 同一个场景或二进制文件只有一个主要写入者。跨团队使用临时成果时，标明来源分支、Commit、版本和已知限制。

## 6. 统一报告位置

每个成员在自己的分支提交：

```text
reports/
  day-01/A/
  day-01/B/
  day-01/C/
  day-02/A/
  day-02/B/
  day-02/C/
  ...
```

每个阶段按实际需要提交：
- `PLAN.md`：目标、方案、依赖和并行分工。
- `RESULTS.md`：真实完成内容和验证结果。
- `EVIDENCE.md`：截图、录屏、Commit、工程/资产位置。
- `BLOCKERS.md`：阻塞、复现、降级、需要谁提供什么。
- `HANDOFF.md`：交给 A/B/C 的可复用结果和接口信息。

不要求为了格式创建空文件。大型录屏放共享存储，Git 中保留链接和时间点。

## 7. 每个阶段结束后的决策

阶段状态只允许：
- `APPROVE`：通过，进入下一阶段。
- `REVISE`：保持阶段，按反馈修改。
- `REJECT`：方向错误，回到方案/白盒。
- `BLOCKED`：外部依赖或工具阻塞，局部冻结并继续其他工作。

如果时间已到但 Gate 未通过，不得为了赶日历而把失败标成通过。总设计师可以批准缩小范围、切换降级方案或调整后续里程碑。
