## 0. 本方案要先解决的一个矛盾

任务包（`TASK.md`）与世界文档（`docs/worlds/01-DESK-WORLD.md`）在**铅笔盒小镇的角色**上不一致：

| 来源 | 说法 |
|---|---|
| `TASK.md`「主玩法闭环」第 1 步 | 玩家看见峡谷**另一侧的目标** → 小镇是**终点** |
| `01-DESK-WORLD.md` §3 | 铅笔盒小镇是「**站点入口**、居民生活、探险工作间」 |
| `01-DESK-WORLD.md` §5 第 6 步 | 过桥后「**对岸小镇**出现可观察反馈：灯亮、居民上路、地图更新」 → 小镇是**反馈方** |

**我的处理（提案，非擅自变更）：** 把铅笔盒**一分为二**——同一个铅笔盒被一道裂口分成「近岸」与「对岸」，两者是**同一件物件的两半**。

这同时满足三种说法：
- 玩家**从近岸出生**（= 站点入口，工作间/地图墙在此）；
- 近岸能**看见对岸的暖灯**（= 第一眼目标）；
- 过桥后到达**对岸**，那里的灯亮起、居民开始用路（= 反馈）。

而且它带来一个免费的主题收益：**这个小镇是被"断开"的，玩家把它的两半重新接上**。物件用途重构（尺子变桥）与叙事（把分开的地方连起来）指向同一件事，不是两张皮。

> 需要总设计确认。若否决，方案 B 提供不依赖此设定的替代布局。

## 1. 尺度基准（实测 + 提案）

### 1.1 实测部分 `[CONFIRMED-BY-PROBE]`

在本机编辑器实测（`EVIDENCE.md` §4）：

| 参数 | 实测值 | 来源 |
|---|---|---|
| 编辑器默认角色身高 | ≈ 1.7 m（与场景 1 m 网格对照） | 截图 `wb-player-02.png` |
| `moveMaxSpeed` | **4.0** | `scene.data/SerializePcgData.json` |
| `jumpMaxHeight` | **1.0** | 同上 |
| 场景容量上限 | **4000**（当前 207） | 编辑器顶部容量条 |

### 1.2 一个关键方向选择 `[PROPOSED]` — 需总设计确认

编辑器**不支持缩小玩家**（默认角色固定约 1.7 m）。所以"微缩"只有一条路：

> **让书桌世界的物件变成巨物**，而不是让玩家变小。

这反而更符合世界文档「把日常物件转化为地理」的定义。于是尺度表：

| 现实物件 | 现实尺寸 | 世界中尺寸 | 相对玩家身高 | 空间角色 |
|---|---|---|---|---|
| 木尺 | 300 mm | **30 m** | 17.6× | 尺子桥（跨 10 m 裂口） |
| 硬皮厚书 | 240×170 mm | **9 × 6 m** | 5.3× | 书谷崖壁 |
| 第二本书 | 210×148 mm | **7.5 × 5 m** | 4.4× | 书谷对壁 |
| 铅笔 | 175 mm | **22 m** | 12.9× | 支路轨道/独木桥 |
| 橡皮 | 45×25 mm | **4 m** | 2.4× | 可推配重（P1） |
| 铅笔盒 | 200×80 mm | **14 × 9 m** | 8.2× | 小镇底座 |
| 马克杯 | 95 mm | **9 m 高** | 5.3× | 远景港口 |
| 台灯 | 400 mm | **11 m 高** | 6.5× | 远景太阳 |

**读法校验：** 尺子（30 m）必须比书（9 m）**明显更长**——这是让玩家一眼认出"那是尺子"的前提。上图比例已验证这一点。

### 1.3 一个必须记录的风险

`jumpMaxHeight = 1.0 m`，而橡皮高 1.8 m、铅笔直径 1.7 m。
→ **玩家跳不上任何主要物件**。所有可达高度必须靠**坡道/台阶/书页边缘**解决，不能靠跳。
这条约束直接决定了下面两个方案的路线设计：**不允许设计"跳上去"的路线**。

## 2. 方案 A｜「裂谷—两端」（推荐）

### 2.1 一句话

> 玩家从被裂口分开的书桌**近岸**出发，沿书谷走到底，用尺子把 10 m 裂口接通，走到**对岸**的小镇；对岸灯亮，同时露出一条只有过了桥才看得见的支路。

### 2.2 空间结构

```
                    ┌────────── 对岸 (TARGET) ──────────┐
                    │  铅笔盒小镇·对岸                   │
                    │  · 暖窗小屋 ×3                     │
                    │  · 工作间入口（反馈后开）           │
                    └───────────────▲───────────────────┘
                                    │  ★ 支路：书页坡道 → 台灯基座观景点
                                    │
        ══════════════ 10 m 裂口 ══════════════
              ↑ 尺子桥（玩家搭）
                                    │
    ┌───────────────────────────────┴───────────────────┐
    │  书谷（主路线，宽 ~6 m 走廊）                       │
    │   书 A(9m) ║ 玩家通道 ║ 书 B(7.5m)                 │
    │   地面：书封皮 → 书页边缘 → 书脊（三级台阶）        │
    └───────────────▲───────────────────────────────────┘
                    │
              ┌─────┴─────┐
              │  出生点    │  铅笔盒小镇·近岸
              │  工作间/地图墙 │
              └───────────┘
```

### 2.3 逐项回答（对着任务包的要求）

**① 玩家入口和第一眼看到的目标**
出生在近岸工作间前的木台上。**正前方 55 m 处、比视线略低**，能看到对岸铅笔盒的 3 扇暖窗（唯一暖光源）。书谷在左手边形成高墙，右手边是裂口。**玩家第一眼看到的是"光"，不是"路"**——光就是目标。

**② 书谷与桌面尺度的参照**
玩家脚下是书封皮的纸面（近景材质：纸纤维、压痕、磨损边），两侧书脊高 7–9 m（约 4–5 个玩家高），远处台灯灯罩高 11 m。参照系是**三级的**：脚边纸纹 → 两侧书墙 → 远处台灯。玩家不需要 UI 提示就知道自己很小。

**③ 尺子桥谜题的阻隔 / 线索 / 动作 / 结果**

| 要素 | 设计 |
|---|---|
| **阻隔** | 10 m 裂口，深色（桌面木纹向下延伸），**不能绕行**（两端被书阻挡），不能跳过（jump=1.0 m） |
| **线索** | G1 尺子就横躺在裂口近岸一侧，**半截悬空**——这个姿态本身在说"它能过去"；G2 裂口两侧地面有**两道平行的浅槽**（尺子滑进去的导轨）；G3 对岸裂口边缘有一块**橡皮挡块**，暗示需要一个平坦的跨越物 |
| **动作** | 走近尺子 → 出现交互提示 → 玩家选择「推入导轨」→ 尺子沿两道槽**滑过裂口**并卡住（吸附/预设状态，非自由物理，符合世界文档 §4 `[CONFIRMED]`） |
| **结果** | 尺子成为实体可行走面 → 对岸暖窗**由 1 扇变 3 扇并变亮** + 一段环境音（远处木地板共振）+ 地图墙更新 |
| **通过** | 玩家**亲自走过**尺子（30 m 长、0.8 m 宽，比玩家宽，安全边界清楚） |

**④ 铅笔盒小镇如何成为可达目标**
就是上面的"对岸"。可达性由**唯一通路**保证——只有桥接好才能到。这符合"目标可见但不可达"的张力。

**⑤ 可选路线提供什么新视角**
过桥后，对岸小镇右侧有一条**书页卷成的坡道**（不是台阶，是揉皱的书页）上升到台灯基座。
奖励**不是收集物**，而是：
- 一个**俯瞰点**：从台灯基座高度回看，能同时看到书谷、裂口、尺子桥和自己的来路——**这是全图唯一能看懂"我刚才做了什么"的位置**；
- 一个**捷径**：从观景点可以沿台灯电线滑回近岸工作间（省一次往返）。

**⑥ 远景如何暗示桌面之外**
- 右后方：**马克杯（9 m）**，杯口有雾气，作为港口远景（不进入，符合"不做第二张地图"）；
- 正后方窗外：**冷蓝色夜空**（实测可用 `MarsWorld_sky01_night01.tga`）；
- 桌面边缘之外：一片**更暗的桌面继续延伸**，上面有另一个微弱的暖光点（暗示别的"城"存在）。

### 2.4 玩法闭环（对照 `TASK.md` 的 8 步）

| # | 要求 | 方案 A 对应 |
|---|---|---|
| 1 | 看见峡谷另一侧的目标 | ✅ 对岸 3 扇暖窗 |
| 2 | 观察到尺子/支点或可利用物件 | ✅ 悬空的尺子 + 双导轨槽 + 橡皮挡块，三条冗余线索 |
| 3 | 做出选择、摆放或触发 | ✅ 推入导轨（吸附） |
| 4 | 通路状态可见变化 | ✅ 尺子位移 + 对岸灯变化 |
| 5 | 玩家实际走过新路线 | ✅ 亲自走 30 m |
| 6 | 对岸出现反馈 | ✅ 灯 1→3、环境音、地图墙更新 |
| 7 | 错误操作可恢复 | ✅ 见 §2.6 |
| 8 | 尽可能替代解法 | ✅ 见 §2.5 |

### 2.5 替代解法（两条，均有代价）

| 解法 | 做法 | 代价（保证不是免费最优） |
|---|---|---|
| **A · 主解：尺子** | 推入导轨 | 无额外代价，但需要理解"推"这个动作 |
| **B · 替代：铅笔 + 橡皮配重** | 把 22 m 铅笔横搭在裂口上，但铅笔**是圆的会滚**，必须用橡皮（4 m）在近端做挡块 | 需要多走 20 m 去支路取橡皮；铅笔直径 1.7 m 走起来更窄，**掉落风险更高**（掉下去会被送回近岸，不死亡） |
| **C · 降级：书页** | 撕下一张书页折成坡道，只够跨 4 m | **不够跨 10 m**，只能到达裂口中间的橡皮岛，从那里仍需尺子。即"降级解法只能缩短距离，不能取消核心动作" |

> **设计意图：** 任何解法都必须"改变通路并亲自通过"，没有一条路是跳过玩法的。

### 2.6 失败恢复

| 失败情形 | 恢复 |
|---|---|
| 尺子推歪/掉进裂口 | 在裂口底部**停留 3 秒**，尺子被"桌面下的一股气流"托回近岸原位（有动画与音效）；或玩家可直接走回近岸重新取 |
| 从尺子上掉落 | `respawnHeightY = -50` 实测存在，落到阈值即回最近安全点（近岸木台），**不扣任何东西** |
| 玩家推不动/找不到交互点 | 尺子在**未被交互前持续有轻微高光脉动**（避免"不知道能点"）；三次靠近无操作后，对岸暖窗做一次"呼吸"变化，把注意力重新引向目标 |
| 走错方向 | 书谷是单一走廊，无岔路，不会迷路 |

## 3. 方案 B｜「环绕书谷」（备选，明显不同）

### 3.1 与 A 的核心差异

A 是**线性 → 一次跨越**；B 是**环形 → 一次下降**。

> 玩家从书谷**顶端**出发，目标（小镇）在**谷底**可见。尺子不是桥，而是**滑道**：玩家把尺子架在书脊之间，沿着它从高处滑到谷底。

### 3.2 空间结构

```
         ┌── 出生：书脊顶端（高 9 m）────────┐
         │  · 能俯瞰整个书谷与谷底小镇        │
         │  · 目标就在正下方（低，不是远）    │
         └──────────────▲──────────────────┘
                        │ 沿书脊边缘下降到第二平台（书签台阶）
                        │
         ┌──────────────┴──────────────────┐
         │  第二平台：尺子架在这里            │
         │  · 两道书脊缺口构成"轨道支座"      │
         └──────────────▲──────────────────┘
                        │  ★ 尺子滑道（倾角约 18°）
                        │
         ══════ 谷底 ═════════════════════════
         │  铅笔盒小镇（谷底，环绕四周是书墙）  │
         │  · 玩家从滑道末端落地              │
         └──────────────────────────────────┘
```

### 3.3 各自回答

| 项 | 方案 B |
|---|---|
| 入口/第一眼目标 | 书脊顶端，目标在**下方**（垂直张力而非水平距离） |
| 尺度参照 | 起点最高（9 m），玩家体验"从 5 个自己高往下看" |
| 阻隔/线索/动作/结果 | **阻隔**＝书脊间 12 m 垂直落差且无台阶；**线索**＝尺子已卡在支座上但**方向不对**（斜着），且书脊缺口只有两个；**动作**＝转动尺子到 18° 倾角并推入支座；**结果**＝尺子成为滑道，谷底灯亮 |
| 小镇可达 | 谷底，滑道末端即到达 |
| 支路 | 书脊背面有一条**书签隧道**，直通谷底（捷径），但需要先发现书签的隐藏位置 |
| 远景 | 从谷底往上看，四周书墙 + 顶部台灯 → 井底视角，更强"被包裹"感 |
| 玩法闭环 | 同样满足 8 步，但"通过"变成"滑下" |

### 3.4 我在 Day 1 结束时的推荐

**推荐方案 A。** 理由：

1. **A 的"通过"是走，B 的"通过"是滑。** 世界文档要求"玩家亲自走过新路线"，走比滑更符合字面，也更容易在编辑器里用刚体验证（B 的滑道需要连续碰撞与摩擦，技术风险高）。
2. **A 的裂口是"世界坏了"，B 的高低差是"世界本来就这样"。** A 让玩家的操作具备**修复**意义，更契合"把分开的地方连起来"。
3. **技术风险：** B 依赖坡度行走与滑行，而实测 `jumpMaxHeight=1.0`、无坡道 API（`BLOCKERS.md` B-03），B 的验证成本更高。
4. **B 的支路（书签隧道）是隐藏通路，容易变成"藏东西"**，而 A 的支路是"登高回望"，更能服务于主题。

> 但 B 有一个 A 没有的优点：**垂直尺度反差更强烈**。如果 Gate D2 的白盒显示 A 的书谷不够震撼，B 的井底视角可以作为补救方向。建议保留 B 作为备选而非废弃。

| 字段 | 内容 |
|---|---|

### DESK-003｜尺子导轨支座（桥接端）

| 字段 | 内容 |
|---|---|
| 玩家用途 | 给出"尺子该往哪去"的空间线索；吸附判定点 |
| 观察距离 | **near**（玩家会踩上去） |
| 比例 | 2.0 × 0.4 × 1.2 m（两个，裂口两岸各一） |
| 形体 | 浅槽/凹口，形状与尺子端部吻合；刻意的"人造"痕迹（不是自然岩石） |
| 材质目标 | 与桌面同木质，但**边缘有磨损**表明被反复使用 |
