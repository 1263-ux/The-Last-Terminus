## 1. 本轮解决的三个真实问题

Day 1 结束时白盒"导入了但看不见"。本轮把它查清并修好了，三处都是**实测坑**，写下来避免团队重复踩。

### 1.1 GLB 缺少 NORMAL → 物体只投影、不显示 ★ 最贵的坑

| 项 | 内容 |
|---|---|
| **症状** | 白盒对象在场景树里存在、有正确位置、**投射了正确的阴影**，但相机里完全看不见表面 |
| **误判过程** | 先后怀疑：地形遮挡 → 物体在原点而出生点在 148 m 外 → 相机朝向反了 → 被地形埋住。全部排除后才发现是法线 |
| **根因** | `tools/make_whitebox.py` 早期版本写出的 GLB 只有 `POSITION + COLOR_0 + 索引`，**没有 `NORMAL`**。引擎的 shadow pass 只需要深度，所以阴影照画；但主 pass 需要法线做光照，缺失时表面不被绘制 |
| **修复** | 在 `write_glb()` 中按面法线累加求平滑顶点法线，写入 `NORMAL` accessor |
| **验证** | 修复后同一批几何体立刻可渲染（`evidence/day-01/09~12`） |

> **给 A/C 的结论：** 只要几何体"有阴影、没表面"，先查 `NORMAL`，不要去调相机和坐标。
> 这条对 C 的 AI 地形/程序化资产同样适用。

### 1.2 出生点与相机朝向（实测，结论修正过一次）

| 项 | 实测值 |
|---|---|
| 出生点 | `(119.741669, 80.0, 88.64061)`，`rot = (0,0,0,1)` 单位四元数 |
| 出生点节点 | `nodeName=出生点`，`tag=BornPoint`，`physicsColliderData=null` |
| 相机朝向 | **仍未确定性测出**，见下 |

**我在这里走过一次弯路，必须记下来：**
先用"把道具放 +Z / 放 −Z 各拍一张，看哪个出现在画面"来二分朝向。两次都没在画面里看到道具，
于是先后得出过"朝 +Z"和"朝 −Z"两个相反结论，**都是错的**。

真正有效的证据是**按键行走**：注入 `S`（后退）后角色移动，画面里开始出现黄色尺子末端与铅笔盒边缘
（`evidence/day-01/15-playerview-props-entering-frame.jpg`）。这说明道具确实在**视野边缘之外，
而不是在背后**；也说明"道具是否可见"取决于**距离和视野角度**，不是简单的 +Z/−Z 二分。

**结论（诚实版）：**
- 出生点 `rot` **不能**用来推断相机朝向（单位四元数也照样有朝向）；
- 单纯"放一个物体在某侧然后截图"**不足以**判定朝向，因为默认第三人称相机有俯角与偏移；
- 想真正测出朝向，需要读相机 transform（`runtime lua eval` 需要先选 `--script/--binding/--global`，
  本轮未打通），或把物体放到**离玩家足够近**（<8 m）再二分。

**这条已标为 Day 2 首要技术探针，不在本轮假装解决。**

### 1.3 桌面几何尺寸与玩家的关系

早期桌面是 40×30 m 的单块板，放置后**玩家站在板内部**，相机被板体包住 → 什么也看不见。
修复：把桌面重做成"近岸板 + 10 m 裂口 + 对岸板"，并把锚点设在让玩家站在近岸板**上表面**。


这进一步支持 `BLOCKERS.md` B-03 的判断：**尺子桥必须用锚点/预设状态实现，自由摆放不可行**。
或者——把尺子缩短到 12 m（仍是 7× 玩家身高，识别度不受影响）。**这是本轮提出的一个具体修正建议，见 §5。**

## 6. 工具与可复现性

本轮所有几何由 `tools/make_whitebox.py` 生成（纯 numpy，无 Blender、无第三方库），
放置脚本 `tools/place_whitebox.ps1`。清场/重摆的命令序列见 `EVIDENCE.md` §3。

**关键 CLI 经验（已写入 HANDOFF 给 A/C）：**
- 负坐标/负节点 ID 必须用 `=` 形式：`--position=-13,0,-6`、`--object=-12562`
- `scene remove` 只接受**位置参数**的形式（`scene remove -667818639`），传 `--args` 静默失败
- `scene import` 报"超时"时**多数实际已 committed**；用 `scene operation <requestId>` 核实，不要换新 ID 重试（会重复实例）
- 运行中改场景 → 之后 `runtime status` 会长期卡 `loading`。稳定节奏：`stop → 改 → save → start → 立刻连续截图`
- 编辑器卡死时用 `instance stop` + `instance start --project <路径> --mode foreground` 可以干净恢复（本轮用过 3 次）
