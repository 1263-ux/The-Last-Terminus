## 1. 本轮目标

Day 1 的目标不是做出好看的花园，而是**暴露错误假设**。具体四件事：

1. 用成熟作品反推出「浮空花园作为可玩空间」的真实设计规则，而不是视觉参考拼贴。
2. 提出至少两种空间拓扑并做出有理由的选择，理由不能是"更好看"。
3. 用新版造世界编辑器实测，确认哪些能力真的存在、哪些是幻想。
4. 交付一份可被 A 接收的入口/出口/尺度约定，以及可被总设计师评审的 Asset Card。

Gate 判定依据是 `tasks/004-c-floating-garden/GATES-AND-ACCEPTANCE.md` 的 **C-G1**。

### 3.2 参考研究

`REFERENCE-STUDY.md`，564 行。覆盖 Sky / Monument Valley / Ori / Journey 四款，每款都有：具体场景、观察点、可迁移方法（编号规则）、不能照搬的内容。三条硬结论：

1. **可走面材质语言必须全局唯一，且绝不复用为装饰。**
2. **禁止任何依赖单一视角才成立的"视觉连桥"**，所有连接必须在三维中真实成立。
3. **观景点必须同时看见"来路"和"下一个目标"**，否则只是截图点。

第 2 条直接约束了本世界的技术路线：Monument Valley 的签名手法依赖固定相机，我们是自由视角第三人称，因此不能照搬。这条结论在当天就被白盒验证了必要性。

### 3.3 空间拓扑

`SPATIAL-PROPOSALS.md`，561 行。三方案 A / B / C，每方案九个字段（入口、地标体量、三层高度、主要连接、隐藏路径、安全落脚点、视线、终点奖励、失败模式），加对比表与推荐理由。

推荐 **方案 C「反向生长」的双层叠加结构**：温室吊在入口浮岛的**下方**，玩家从入口就能看见目标，但目标是向下的；根系从头顶掠过，玩家要先理解"这座花园朝反方向生长"，才会发现根系本身就是可走路径。这让"原来这里也能走"成为**结构性**发现，而不是藏在侧面的支路。

选它的理由（对比表结论，非审美）：目标可见性 3/3、路线发现强度 3/3、迷路风险最低、白盒成本最低（比 A 少一个环段，比 B 少一层平台）。代价是倒悬温室在自由视角下的"倒"必须靠结构而非错觉传达，这被列为 Day 2 首要验证项。

### 3.4 编辑器技术探针（真实执行，见 `PROBE-RESULTS.md`）

当天真正跑通的：

- 项目创建、实例启动、SCAD 地图离线渲染、预览运行、玩家输入、截图、场景保存、关闭实例后重开并确认白盒仍在。
- 用 Three.js 作者源做出 63 节点白盒（入口浮岛 / 根系通道 / 倒悬温室 / 空中平台链 / 花冠观景点 / 远景浮岛 / 路线锚点），validate → archive → attach → build → 存档到场景 → 运行。
- 玩家真实走通根系通道：`x 134 → 117.6`，`y 60 → 61.5`，全程踩在可走面上，无坠落。
- 运行时用程序驱动一块平台上升 3.0 m，并把玩家一起带上去（`carried: true`）。

当天确认**不存在**的能力：

- 浮空岛地形：AI 地形服务明确回复「地图主体是漂浮在空中的浮岛，暂不支持」。
- 内置移动平台组件：组件表里没有任何 motion / platform / animator 驱动位移的字段。移动只能靠 Lua/JS 程序驱动。

### 3.5 玩法流程

完整闭环写在 `SPATIAL-PROPOSALS.md` §8，摘要：

看见倒挂温室 → 直线路径被 3 m 断口切断 → 抬头看见从头顶掠过的根系底面（第一次路过会以为是装饰）→ 走到岛缘侧面才发现根尖有可上的斜坡 → 爬上根系通道 → 抵达温室下方平台 → 空中平台链上到花冠观景点 → 回望来路。

线索是**环境物件**（根系的粗细变化、根皮朝向、根尖接地），不是 UI 箭头。

## 6. 阻塞与风险

详见 `BLOCKERS.md`。三条要点：

1. **AI 地形不支持浮岛**（B-03）——影响地形方案，不影响玩法闭环。
2. **GLB 材质在编辑器运行时被统一覆盖为 `EnvLit_AI_Mat`**（B-02）——这是当天最严重的发现。Three.js 里设的颜色、`appearanceData` 组件、运行时改 `sharedMaterial.color` 全部无效。所有分层配色必须走编辑器原生材质系统，且 Day 2 必须重做一次配色验证。
3. **PCG 地形卡在参考图确认**（B-04）——CLI 的 `generation answer` 对带 `pcg` 字段的题目无法用任何已试格式回答，已尝试 8 种。地形续轮暂停，不影响白盒。
