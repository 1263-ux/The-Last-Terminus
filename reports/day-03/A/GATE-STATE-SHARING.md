# 门禁状态共享技术记录

> Owner：成员 A
> 目的：为 B 的 E1（状态门禁）方案提供技术参考，避免重复踩坑

---

## 问题

Trigger+Teleport 能实现门禁拦截（未解锁→传送回），但**解锁和门禁两个触发器之间无法共享状态**。

## 已尝试的 4 种方案

### 1. `_G` 全局变量 —— FAIL

```lua
-- unlock script
_G.gateActivated = true

-- gate script
if _G.gateActivated then return end  -- 读到 nil
```
**原因**：Lua 脚本实例间不共享 `_G`。

### 2. `local activated`（单脚本）—— FAIL

同一个 Lua 脚本的不同绑定有**独立的 `local` 变量**。
解锁垫的绑定设 `activated = true`，门禁的绑定读到 `false`。

### 3. 节点位置标志 —— FAIL（部分有效）

状态节点初始在 (119.74, 78, 82)。解锁脚本把它移到 (0, 0, 0)。
门禁脚本读位置判断是否已解锁。

**结果**：解锁确实触发（状态节点移到 0,0,0），但门禁仍拦截。
**原因**：`findState()` 在门禁脚本中可能找不到跨实例的状态节点。

### 4. `text3DData` / TextMesh —— FAIL

`text3DData` 平台组件**不创建 Unity TextMesh/TMP 组件**。
Lua/JS 在运行时无法读取其内容。

## 结论

**跨脚本实例状态共享是引擎的根本限制。**

## 可行的替代方案（供 B 参考）

| 方案 | 做法 | 优缺点 |
|---|---|---|
| **A. 单节点单脚本** | 把解锁和门禁逻辑放在**同一个节点**的**同一个脚本**里 | 空间受限（两区域不能太远） |
| **B. 单触发器+位置判断** | 一个大触发器覆盖两区域，脚本内用位置区分 | 需要精确位置判断 |
| **C. 组件值** | 用 `physicsColliderData` 的 `isTrigger` 字段做标志（可读写） | 未验证 |
| **D. 顺序触发** | 解锁垫触发后直接传送玩家到门禁后方（绕过门禁） | 简单但不优雅 |

## A 的推荐

**方案 B（单触发器+位置判断）** 最可行：
- 一个 `triggerData` 覆盖 z=88 到 z=95
- `OnActorTriggerEnter` 中用 `actor.position.z` 判断区域
- z < 92 → 解锁区：设标志
- z >= 92 → 门禁区：检查标志，未解锁则传送回

这样只用**一个脚本实例**，`local` 变量自然共享。
