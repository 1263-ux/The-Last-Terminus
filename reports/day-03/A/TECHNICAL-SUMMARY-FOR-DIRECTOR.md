## 一、核心发现（影响所有玩法设计）

### 1. 物理碰撞：primitive BoxCollider 可阻挡玩家（已纠正）

> **⚠ 本条已按最新证据纠正。旧结论"物理碰撞不参与"是错的，不能再作为全局结论引用。**

**最新结论（B 的开/关墙对照 + 毫米级几何吻合，A 确认）**：
- primitive **BoxCollider 能精确阻挡玩家** —— **PASS**
  - 墙启用：z 卡在 107.53，连续三次推进纹丝不动
  - 墙禁用：z 从 107.53 → 113.42，前进 5.89m
  - 理论阻挡面 = 墙前 96.391 − 胶囊半径 0.160 = 96.231；实测 96.230
- **根因**：控制器**没有 step-up**——0.20m 矮台可平推穿过，1.20m 平台挡住。这是早期观察矛盾的来源，不能推广为"物理碰撞完全不参与"。
- **导入 GLB 的 MeshCollider 是否能阻挡玩家**：**NOT TESTED**（运行时节点数为 0，见 B 的 RUNTIME-ENTRY 阻塞）。不要把 primitive 的 PASS 直接当成 GLB 的 PASS。

**对设计的影响**：物理门禁可行；设计总监 §3.2 否决 C4 的依据失效，需重新裁定。Trigger+Teleport 仍是已验证的独立交互机制，在 GLB 阻挡未验证前作为可靠降级。

### 2. Lua `local` 变量不跨帧持久化

**影响**：门禁解锁状态、谜题进度等不能用 Lua 变量存储。
**验证**：6 轮测试（含干净场景单门禁）。
**替代方案**：节点位置存储（`GateStateMarker` z=0/1）——**已验证 PASS**。

### 3. `OnActorTriggerEnter` 在 Teleport 时不触发

**影响**：不能用触发器事件做解锁判断。
**替代方案**：`Update()` 轮询（每帧检查位置）。

### 4. 可见性定律（B 发现）

**公式**：`topY ≤ camY + d × 0.0787`，`d ≥ 5.2m`
**影响**：所有世界布局必须先过可见性检查。
**工具**：`tools/visibility_calc.py`

### 5. SCAD 管线（B 发现）

**区分**：`scene import <裸 GLB>` = 模型资产；**完整关卡**需 SCAD map 管线。
**管线**：`SCAD map → assembly → prefab → build → export → asset import → scene import`
