## 1. 状态 0：物理门真的挡住

```
门中心 z = 91.64，厚 0.40 → 前表面 91.44
胶囊半径 0.16 → 理论停止 91.28

实测：step1 z=91.28 → step2 z=91.28 → step3 z=91.28
```

**三次推进纹丝不动，且与理论值毫米吻合。**

**这是真实碰撞，不是规则门禁。** 此前"物理阻挡不可能"的结论已被
`CORRECTION-COLLISION-WORKS.md` 推翻。

### 1.1 为什么这次能挡住，以前不能

| 差异 | 说明 |
|---|---|
| 用运行时 `CreatePrimitive` 建墙 | 之前多数失败测试用的是 `scene import` 导入节点 |
| 高度 0.80 m | 高于 step-up 阈值（0.20 m 矮台会被平推穿过） |
| 有 BoxCollider、非 trigger | 标准配置 |

**导入 GLB 是否也能挡住，仍未验证**（运行时节点数为 0，见更正报告 §9）。

## 2. 状态 1：激活后放行

激活一次完成三件事：

```
LOOP_GATE        → SetActive(false)   门消失
LOOP_RULER_REST  → SetActive(false)   尺子被"搬走"
LOOP_RAMP + 6 刻度 → SetActive(true)  桥体出现（共 7 个部件）
```

**是替换，不是并存。** 静止姿态被移除，符合 Day-3 对"预先摆两个姿态"的警戒。

### 2.1 放行后的连续行走

```
起点     z = 88.64
step 1   z = 96.42   y = 77.98
step 2   z = 100.98  y = 77.91
step 3   z = 100.98  ← 停住
```

**停在 100.98 不是 bug** —— 那是小镇建筑的前表面（101.14 − 胶囊半径 0.16）。
**玩家走到了终点，被目标建筑本身挡住，这正是"到达"。**

## 4. 与设计基线的关系

### 4.1 玩法完全对齐

`PROMPT-B.md` §5 要求的核心流程：

> 玩家出生 → 看见书谷和小镇目标 → 观察尺子与两个支点 → 理解尺子用途 →
> 主动进入整理/交互 → 确认后 REST 隐藏、完整桥体出现 → 玩家连续走过桥 →
> 小镇入口灯亮/环境回应 → 地图或日志记录第一条道路

**前 8 步已实测成立。** 第 9 步（地图/日志）未做——UI 不支持时用环境反馈替代，
而暖窗点亮已作为环境反馈实现。

### 4.2 但有两处需要说明

| 项 | 状态 |
|---|---|
| 用的是运行时 primitive，不是真实 GLB | ⚠️ 机制证明，非资产验收 |
| 激活用 lua eval，不是玩家 GUI 交互 | ⚠️ 显式触发，但不是"玩家按键" |

**第 2 点是当前最大的缺口**：我用命令触发激活，不是玩家在游戏里按 E。
要补成真交互，需要 Trigger 绑定（依赖 C 的配方或 GUI）。
