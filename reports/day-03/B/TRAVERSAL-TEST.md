## 2. 门禁：判定对，执行不了

### 2.1 现象

```lua
if (not solved) and p.z > gateZ then
    pl.transform.position = v3(p.x, p.y, spawnZ)   -- 写入
    r.result = "REPELLED_TO_SAFE_POINT"
end
```

返回：

```
result : REPELLED_TO_SAFE_POINT    ← 判定正确
player : 119.75, 77.91, 102.83     ← 位置没变
```

### 2.2 原因（已在此前多轮验证）

`Player_1` 是 `NetworkActor` 驱动的运动学刚体，
**控制器每帧写 transform**，脚本写入立即被覆盖。

这与 `COLLISION-REPRO.md`、`TECH-CAPABILITY-MATRIX.md` 的结论完全一致：
**位置可写，但不可持久。**

### 2.3 这意味着什么

门禁**不能靠传送实现**。可行方案只有：

| 方案 | 机制 | 可行性 |
|---|---|---|
| **A. 视觉阻断 + 不设门禁** | 玩家可越过，但不告诉他"该往哪走" | ✅ 简单，但失去谜题 |
| **B. 断口真实存在物理缺口** | 掉下去 → `respawnHeightY` 引擎自动复活 | ✅ **引擎级，值得试** |
| **C. Trigger 绑定脚本** | 需 GUI 绑定 | ⏸ 依赖 C 的配方 |

**方案 B 最有希望**：`respawnHeightY = -50` 是引擎配置，
玩家掉到 -50 会自动复活 —— **不需要我写传送代码**。

## 3. 暖窗反馈：颜色有效，发光无效

| 尝试 | 结果 |
|---|---|
| `SetColor("_BaseColor")` | ✅ **生效**（绿 → 亮绿） |
| `EnableKeyword("_EMISSION")` + `SetColor("_EmissionColor")` | ❌ 无可见发光 |

**结论：用颜色变化做反馈，不要依赖 emissive。**

证据 29 里 5 扇窗从暗绿变鲜绿，变化清晰可辨。
