# ACCEPTANCE & REPORT｜阶段验收与汇报规范

## 1. 验收角色

- A 自检公共模块和技术交接。
- B 自检书桌站；C 交叉 Review B。
- C 自检失重花园；A 交叉 Review C。
- 总设计师负责最终设计验收和范围决策。

交叉 Review 不是替对方重做，而是从玩家视角找问题。

## 2. 阶段 Gate

### Gate 0：理解一致
通过条件：
- 每人能用自己的话说明项目定位、负责范围和明确不做什么。
- 所有不确定能力被标记为 TO-VERIFY。
- 不擅自修改已确认设定。

### Gate 1：编辑器和交接
通过条件：
- 项目可保存并重新打开。
- GLB 和 WPRE 的导入结果有实测记录。
- Git 克隆/交接至少完成一次真实测试。
- 若完整项目不能迁移，已验证独立资产交接降级方案。
- 项目文件、缓存、临时文件边界清楚。

### Gate 2：空间白盒
通过条件：
- 列车公共空间、书桌站、失重花园均有白盒。
- 入口、主路线、地标、出口可辨认。
- 两个可玩世界从出生点到目标点能够完整走通（玩法可以暂时用占位触发）。

### Gate 3：玩法探针
通过条件：
- 书桌站证明“重新利用日常物件改变通行方式”。
- 失重花园证明“观察空间结构发现非直线路线”。
- 两者玩法不同，不是换皮。
- 失败可恢复，不会把玩家永久卡死。

### Gate 4：进入精细美术
通过条件：
- 总设计师确认白盒方向。
- 关键模型需求有明确资产卡和参考图。
- 已知编辑器限制有降级方案。
- 没有未解决的 P0 技术阻塞。

## 3. 统一问题等级

- **P0：** 无法打开项目、无法导入关键资产、玩家无法继续、场景无法保存、世界无法连接。
- **P1：** 核心玩法不成立、主路线不清晰、严重穿模、关键模型/材质错误、性能明显异常。
- **P2：** 普通装饰、次要音效、非关键细节、可选支路的小瑕疵。

一周冲刺优先解决 P0 和影响体验的 P1。不要为了 P2 装饰推迟核心闭环。

## 4. 每日汇报模板

每位成员每天提交一份简短报告：

### 今日目标
- 今天原计划完成什么？

### 实际完成
- 完成了哪些具体内容？
- 对应 Git commit / 文件路径 / 编辑器项目位置？

### 证据
- 编辑器截图（远景、中景、近景）。
- 从出生点开始的连续录屏。
- 导入/交互/保存等关键操作的录屏或截图。

### 与设计基线的偏差
- 哪些地方与任务书不一致？
- 是否需要设计决策？

### 技术与资产
- 使用了哪些编辑器功能？
- 使用了哪些 GLB/WPRE/贴图/音频？
- 哪些属性保留或丢失？
- 资产来源和授权是什么？

### 问题与阻塞
- 复现步骤。
- 影响等级 P0/P1/P2。
- 已尝试的解决方式。
- 推荐降级方案。

### 下一步
- 下一工作块。
- 预计交付证据。

## 5. Review 反馈格式

Review 人不要只说“不错”或“感觉不对”。按以下格式反馈：

- 观察到的问题：
- 玩家受到的影响：
- 对应证据：
- 建议修改：
- 优先级：
- 是否阻塞下一阶段：

- [ ] 失重花园有完整空间路线发现体验。

- [ ] 资产清单、来源、授权齐全。
