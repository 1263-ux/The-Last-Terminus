# COMMON BRIEF｜全体成员共同执行说明

## 1. 项目是什么

《天空列车的最后一站》是一段由天空列车连接三个不同世界的短篇探索旅程。

本轮只做：
- 共享列车空间。
- 世界 01：书桌站《桌面以下》——可玩。
- 世界 02：失重花园——可玩。
- 世界 03：云海尽头——纯展示。

三个世界必须有不同的体验职责：
- 书桌站：微观尺度、日常物件再利用、环境谜题。
- 失重花园：空间方向、垂直结构、路线发现。
- 云海尽头：宏大景观、观景、旅程收束。

《梦境邮局》已经退出项目，不得重新加入。不得擅自增加天文小镇或其他新世界。

## 2. 这次要坚持的四个产品支柱

### A. 世界观与故事根基
世界设定为美术、音乐和玩法提供依据。当前列车起源、云隙本体、终点真相仍是开放设定。可以提出创意，但必须标记为 PROPOSED，不能擅自写成正式设定。

### B. 美术
目标是高辨识度、可读、材质可信的奇幻场景。核心地标优先精修；普通装饰复用成熟资产。禁止把不同风格的免费模型无筛选地堆在一起。

### C. 音乐与声音
音乐不是最后一天的装饰。每个世界需要明确情绪、环境声和交互反馈。先研究候选曲目与授权，不要直接使用授权不明的音乐。

### D. 玩法
玩家必须有明确行为。每个可玩世界至少有：目标、观察线索、玩家动作、即时反馈、完成状态、可继续探索的内容。两个世界不得使用同一套谜题换皮。

## 3. 工具生产链

- Agent：研究、拆任务、写提示词、整理资产需求、检查结果和记录问题。
- Tripo：按批准的资产需求生产少量关键 3D 模型，不负责整个场景。
- Blender：检查模型比例、朝向、原点、法线、UV、材质、贴图、网格和碰撞代理；按目标编辑器要求导出。
- 新版造世界 AI 编辑器：地形、场景布置、资产导入、组件/交互配置、预览和运行测试。

不要默认 Unity + Douyin World SDK 的功能适用于新版造世界 AI 编辑器。不要假定 GLB/WPRE 的所有材质、动画、碰撞、逻辑和依赖都会完整保留。每一项都要测试。

## 4. Agent 执行规则（特别针对 Vibe Coding）

所有成员的 Agent 必须遵守：

1. 先读仓库规定文件，再开始工作。
2. 先复述任务目标和验收条件，等待成员确认理解；不要自作主张扩展范围。
3. 把任务拆成 30–90 分钟可验证的小步骤。
4. 每完成一步，保存工程并提供证据。
5. 先做白盒和最小功能，再做高质量美术。
6. 不得凭空声称编辑器支持某功能。
7. 不得只凭概念图声称场景已完成。
8. 不得删除、重命名或移动编辑器原生项目文件，除非已验证安全。
9. 不得覆盖其他成员负责的文件或场景。
10. 遇到阻塞，先提交：现象、复现步骤、截图/录屏、尝试过的方案、建议降级；不要用一大段猜测掩盖问题。

### 每次执行循环

`读任务 → 复述目标 → 检查依赖 → 制作最小版本 → 编辑器实测 → 截图/录屏 → 自查 → 提交结果`

## 5. 资产生产规则

每个模型在生成前必须有资产卡：
- Asset ID。
- 所属世界。
- 使用位置。
- 玩家是否会近距离观察/交互。
- 参考图。
- 模型方式（现成资产 / Tripo / Blender / 编辑器内生成）。
- 目标格式（优先按编辑器已验证支持的 GLB/WPRE）。
- 预计尺寸和比例参照。
- 材质/贴图需求。
- 碰撞需求。
- 授权来源。
- 验收方式。

优先级：
- P0：玩家会接触的核心物件、列车、主地标。
- P1：主路线建筑、植物、环境组件。
- P2：远景装饰、重复小物件。

不要为 P2 装饰占用大量 Tripo 额度或人工精修时间。

## 6. 美术评审必须看三种距离

每个世界都要提交：
- 远景：整体空间、主地标和尺度关系。
- 中景：玩家路线、建筑组合和互动点。
- 近景：材质、轮廓、边缘、细节和碰撞。

不能只提交一张氛围图。

## 7. 音频工作要求

每个世界先给出：
- 1 个主音乐情绪方向。
- 2–3 首可试听候选，或明确说明暂时没有合适候选。
- 环境声清单。
- 关键交互音效清单。
- 来源、作者、许可证和署名要求。

没有确认许可前，不得把音乐纳入最终发布版本。不要把音乐候选数量当作完成度。

## 8. 统一交付证据

所有阶段汇报必须包含：
- 实际编辑器截图（至少全景 + 关键细节）。
- 从出生点开始的连续录屏；玩法任务必须录到完整闭环。
- 实际项目/资源文件位置或 Git commit。
- 本轮完成内容。
- 未完成内容。
- 已知问题。
- 下一步建议。

没有真实编辑器证据的内容只能标记为“概念/计划”，不能标记为“已完成”。
