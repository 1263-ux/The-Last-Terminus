## 2. 工作包 A1：确认项目真实结构

### 操作
1. 记录造世界 AI 编辑器版本、操作系统和项目创建方式。
2. 新建一个空白测试项目，命名 `TLT-Editor-Probe`。
3. 保存项目，关闭编辑器，再重新打开。
4. 找到项目实际存储目录，记录文件结构。
5. 在测试项目中添加一个基础模型/物体，再保存并重新打开。
6. 确认哪些文件是工程必需文件，哪些是缓存、临时文件或自动生成文件。
7. 不要在未确认前把任何文件加入 `.gitignore`。

### 交付
`reports/editor-project-structure.md`，包含版本、路径、文件树、保存/恢复步骤和证据截图。

## 3. 工作包 A2：GLB / WPRE 导入和交接测试

### 测试矩阵

| 测试项 | GLB | WPRE |
|---|---|---|
| 能否导入 | 必测 | 必测 |
| 层级/子部件是否保留 | 必测 | 必测 |
| 位置、旋转、缩放 | 必测 | 必测 |
| 材质和贴图 | 必测 | 必测 |
| 动画（如有） | 有动画样例才测 | 有动画样例才测 |
| 碰撞 | 必测 | 必测 |
| 交互配置 | 视资产能力测试 | 必测 |
| 依赖资源是否完整 | 必测 | 必测 |
| 导入后重新打开 | 必测 | 必测 |
| 其他电脑/账号可否重用 | 必测 | 必测 |

### 操作要求
1. 准备一个简单 GLB（含贴图）和一个简单 WPRE 组合资产。
2. 导入测试项目。
3. 检查模型层级、材质、贴图、缩放、碰撞和可交互配置。
4. 保存、关闭、重新打开，检查是否丢失。
5. 将项目/资产提交到测试分支。
6. 让 B 或 C 在另一台电脑克隆/获取测试内容，尝试打开。
7. 若无法迁移完整项目，进一步测试单个 GLB/WPRE 能否作为独立资源交接。
8. 每种失败必须记录具体错误和可复现步骤。

### 交付
`reports/asset-import-handoff-report.md`，明确写出：
- 已验证支持。
- 导入成功但属性丢失。
- 不支持/失败。
- 尚未测试。
- 推荐的团队交接格式。

**不得仅凭扩展名推断 WPRE 一定包含所有依赖、交互或场景信息。**

## 4. 工作包 A3：Git 协作探针

### 操作
1. 确认主项目目录中哪些文件必须版本控制。
2. 检查是否有编辑器锁文件、缓存、自动备份和机器相关配置。
3. 先建立最小 `.gitignore`，每一条忽略规则都要有依据。
4. 提交一个最小测试项目。
5. B 或 C 克隆后打开并做一个无冲突的小修改。
6. A 拉取后重新打开项目。
7. 记录是否存在 GUID/资源引用丢失、WPRE 冲突、项目版本不兼容或文件锁问题。
8. 只有验证后才决定是否启用 Git LFS。不要一开始就把整个目录无差别 LFS 化。

### 交付
`reports/git-collaboration-probe.md`：
- 推荐仓库目录结构。
- 必须提交的文件。
- 可以忽略的文件及原因。
- 是否需要 Git LFS。
- 二进制冲突处理方式。
- 跨电脑克隆测试证据。

## 5. 工作包 A4：公共列车空间白盒

仅在 A1–A3 不阻塞后开始。

### 本阶段只做白盒，不做精细模型

搭建一个最小列车公共空间：
- 一节可辨认的车厢局部。
- 一个车门/连接平台。
- 一张显示三个站点的占位路线图。
- 一个可识别的列车视觉标记（先用占位物）。
- 三个站点入口位置占位，不要求本阶段全部可跳转。

### 设计要求
- 气质：古老、真实、略带神秘；保留可信的机械结构。
- 不复制《崩坏：星穹铁道》的列车造型、标志、UI 或专有设计。
- 首版只做一个紧凑空间，不扩成多节车厢模拟。
- 车厢要能让玩家理解“这里是旅程中枢”，不是一张传送菜单。

### 交付
- 可重新打开的公共列车白盒。
- 入口/出口位置说明。
- 三个世界接入点的坐标或编辑器内可复现定位方式。
- 真实运行录屏。

## 6. A 的 Claude/GPT 使用方式

不要让两个模型同时改同一份工程或文档。建议：
1. Claude：先读文档，提出技术验证计划、检查清单和潜在风险。
2. GPT：独立审阅计划，专门找遗漏、错误假设和未覆盖的失败路径。
3. A：决定执行顺序并亲自验证。
4. Agent 只能生成报告、清单和建议；涉及编辑器操作必须由实际操作者确认结果。

不要把“两个模型都说可行”当作技术验证。
