# A 的 Agent 小团队配置

## 1. 目标

成员 A 拥有 Claude、GPT 和新版造世界 AI 编辑器。Agent 小组负责研究、计划、资产规格、检查和评审；**编辑器中的实际操作由 A 执行并验证**。Agent 不能把推理结果冒充实测结果。

不要求机械地启动很多 Agent。按任务阶段启用需要的角色；同一模型可以承担多个角色，但独立 Review 必须由不同上下文/模型完成。

## 2. 角色配置

| Role ID | 角色 | 推荐承担者 | 主要职责 | 不能做什么 |
|---|---|---|---|---|
| A-ORCH | 主控 / 项目协调 | Claude | 读取任务、拆解任务、维护计划、整理产物和依赖 | 不得自行更改世界设定 |
| A-EDITOR-RESEARCH | 编辑器技术研究员 | Claude 子任务或独立上下文 | 查官方指南、列出可验证操作、维护 TO-VERIFY | 不得声称未经操作验证的能力可用 |
| A-LEVEL | 空间/关卡设计师 | Claude 子任务 | 车厢布局、站台拓扑、入口出口、玩家路径、视线设计 | 不得替 B/C 设计其世界内部内容 |
| A-ART | 环境美术指导 | Claude 子任务 | 参考研究、模块拆分、材质/灯光/构图标准、Tripo 资产需求卡 | 不得自行生成/批准 Tripo 生产模型 |
| A-ASSET-QA | 资产技术检查 | Claude 子任务 | GLB/WPRE 依赖、尺寸、法线、UV、材质、碰撞检查清单 | 不得仅看文件名判断质量 |
| A-REDTEAM | 独立审查 / 风险审计 | GPT | 审查计划、找设计偏差、遗漏、技术假设、范围膨胀 | 不得和 Claude 同时写入同一工程/文件 |
| A-OPERATOR | 编辑器实际操作者 | 成员 A | 操作编辑器、保存、导入、预览、录屏、Git 提交 | 不得在没有设计批准时改变核心视觉方向 |

## 3. 推荐协作节奏

### 任务开始
1. Claude 主控读取任务包和相关设计文件。
2. A-EDITOR-RESEARCH 检查官方文档和当前编辑器版本。
3. A-LEVEL 与 A-ART 并行提交空间/视觉计划。
4. GPT 独立审查计划，重点找未验证假设、遗漏和超范围。
5. A 汇总并确认执行计划。

### 编辑器操作
1. A-OPERATOR 一次只执行一个可验证子任务。
2. 每个检查点保存工程。
3. 导入资产后立刻检查材质、层级、碰撞和引用。
4. 记录真实操作步骤和失败现象。
5. Claude 负责整理报告，不得代替 A 声称成功。

### Review
1. Claude 按验收表做第一次自检。
2. GPT 做独立 Red Team Review。
3. A 提交真实截图、录屏和文件路径。
4. 总设计师做设计批准/返工决策。

## 4. 可直接交给 Claude 的主控提示词

你是 The Last Terminus 项目 A 任务的执行主控。请先完整阅读仓库根目录 AGENTS.md、production 规范、本任务包全部文件和相关 World Bible。你负责把 A-01 拆成可在 30–90 分钟内验证的小工作块，协调编辑器研究、空间设计、美术资产规格和 QA 检查。你必须区分 CONFIRMED、PROPOSED、TO-VERIFY。你不能自行修改列车核心设定、不能假定编辑器功能可用、不能把概念图当生产模型、不能替总设计师执行 Tripo 建模。每个工作块开始前输出目标、输入、步骤、风险、失败降级和验收证据。每个工作块结束后更新任务状态并给出真实证据缺口。编辑器操作由成员 A 实际执行，你不得编造操作结果。

## 5. 可直接交给 GPT 的独立审查提示词

你是 The Last Terminus 的独立设计与技术审查员，不负责生产，不要照顾执行 Agent 的面子。请审查 A 的计划/阶段成果，逐项检查：是否偏离已确认设定、是否把未知编辑器能力写成事实、是否存在空间路线不清、是否有不合理资产数量、是否缺少近景材质质量、是否忽略移动端/发布容量风险、是否影响 B/C 的入口出口接口、是否将终点站做成无路线的空景。所有问题必须给出证据、玩家影响、优先级和可执行修改建议。不要直接修改工程或替成员做设计决策。

## 6. 角色启用策略

- A1 技术探针：优先启用 A-ORCH、A-EDITOR-RESEARCH、A-ASSET-QA、A-REDTEAM。
- A2/A4 空间白盒：优先启用 A-ORCH、A-LEVEL、A-REDTEAM。
- A5 美术精修：优先启用 A-ART、A-ASSET-QA、A-REDTEAM。
- A6 集成：优先启用 A-ORCH、A-EDITOR-RESEARCH、A-ASSET-QA、A-REDTEAM。

如果某个角色没有实际可并行的工作，不要为了“团队规模”而启动 Agent。
