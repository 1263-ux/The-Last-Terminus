# 资产需求与 Tripo 协作方式

## 1. 基本原则

不要提前锁死所有模型，也不要为了填满场景而批量生成资产。

先用白盒确认玩家路线和视觉焦点，再决定哪些资产值得定制。优先级：
1. 玩家会近距离观察或交互的核心物件。
2. 决定世界辨识度的主地标。
3. 普通环境模块和远景装饰。

优先复用已有资产和造世界官方资产库。只有当现有资源无法满足设计目标时，才提出新模型需求。

## 2. Tripo 分工

- 总设计师负责实际 Tripo 生成和关键模型取舍。
- A 负责列车与终点站资产需求。
- B 负责书桌站资产需求。
- C 负责失重花园资产需求。
- 需求提出者应说明用途、比例、观察距离、风格、参考图和可能的部件拆分。
- 总设计师可根据实际 Tripo 能力改写提示词或选择其他方案。
- 模型生成后由对应 Owner 负责 Blender 检查、导入和场景适配。

## 3. 资产需求卡（轻量模板）

每个关键模型只需先说明：
- Asset ID / 名称。
- 它在玩家体验中承担什么作用。
- 玩家会从多远观察它，是否可以互动。
- 希望呈现的形体、材质和风格。
- 参考图及希望借鉴的部分。
- 是否需要可拆分部件。
- 导入后必须满足的条件。
- 还有哪些设计选择可以交给模型探索。

不要在白盒阶段就写几十条模型参数。需求不清楚时先做视觉小样，再决定是否生成。

## 4. A-01 可能需要的关键资产

- 列车外观或车厢识别性模块。
- Hub 内部少量核心视觉物件。
- 旅程路线图/站点识别装置。
- 云海尽头主地标。
- 终点站少量能强化抵达感的特色模块。

这些只是候选需求，不代表全部都必须用 Tripo 生成。A 应先通过场景白盒判断哪些真正值得定制。

## 5. 导入与质量反馈

每个生成模型至少检查：
- 比例、朝向和原点。
- 网格、法线和明显破面。
- 材质与贴图是否保留。
- 是否需要 Blender 修整。
- 碰撞是否适合玩家实际接触。
- 在目标编辑器中保存、重新打开是否正常。

反馈应说明模型问题和实际场景影响，不要只说“质量不好”。
