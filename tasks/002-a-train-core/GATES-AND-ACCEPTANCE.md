# 阶段验收｜以结果为中心

不以文档完成度或 Agent 自述作为验收。以实际项目、画面、试玩和交接证据为准。

## Gate 1｜理解与技术可行性

目标：
- A 理解列车 Hub、世界连接和终点站的体验职责。
- 确认当前项目保存/恢复和 Git 交接方案。
- 对 GLB/WPRE 导入、跨成员交接和场景切换做最小实验。

通过标准：
- 技术能力区分为已验证、失败、待验证。
- 至少完成一次真实资产交接。
- 有明确的连接方案或降级方案。
- 没有把未验证能力写成事实。

## Gate 2｜空间方向成立

目标：
- 列车 Hub 有可识别的空间身份。
- 入口、下一站和返回路径清楚。
- 云海尽头有从列车到观景点的完整空间体验。

通过标准：
- 有白盒或低成本原型。
- 能从玩家视角走通。
- 远景、中景、近景和关键视线均可评审。
- 总设计师确认方向后再投入关键定制模型。

## Gate 3｜视觉与声音样板

目标：
- 关键地标和列车视觉语言成立。
- 材质、光照和构图达到项目质量基线。
- 列车和终点声音能够建立旅程情绪。

通过标准：
- 至少有一个真实编辑器中的视觉样板。
- 关键模型经过导入检查。
- 音乐和音效实际试听，授权清楚。
- 如果动态音乐不可用，有简单可靠的替代方案。

## Gate 4｜集成与完整旅程

目标：
- 接入 B/C 的世界。
- 完整旅程从启程到终点可体验。

通过标准：
- 入口/出口可复现。
- 没有严重软锁、丢失资源或碰撞问题。
- 项目保存后可重新打开。
- 有完整旅程录屏和稳定版本。

## Review 反馈格式

每次 Review 只需回答：
- 哪个体验目标已经成立？
- 哪个问题最影响玩家？
- 有什么证据？
- 建议继续、修改还是换方向？
- 下一轮最值得验证的一个问题是什么？

允许非关键细节暂时不完美。优先解决方向偏差、核心玩法不成立、项目不可恢复和严重集成问题。
