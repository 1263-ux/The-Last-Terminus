## 这份任务包怎么用

它不是逐步操作说明，也不是固定模型清单。它定义：
- 我们要给玩家什么体验。
- 视觉上希望接近什么品质和气质。
- 哪些成熟作品值得研究，应该研究什么。
- 哪些内容必须验证。
- A 最终需要交付什么结果。

具体场景组织、模型拆分、提示词、编辑器操作和实现路线，由 A 的 Agent 团队根据当前工具能力自主完善。Agent 可以提出比文档示例更好的方案，但不能悄悄改变产品方向。

## 关键协作约定

- 总设计师负责关键 Tripo 模型生成。
- A 负责列车 Hub、世界连接、终点站和最终集成。
- B/C 负责各自世界，不由 A 接管其内部制作。
- A/B/C 可以自行研究和提出替代方案，不必照搬文档里的空间草图。
- 任何技术能力以当前编辑器实际操作为准。
- 先做低成本验证和白盒，再投入高成本模型和精细美术。

## 交付目标

最终玩家能够从列车出发，进入两个不同的可玩世界，再抵达云海尽头。列车是共同旅程空间，云海尽头提供情绪收束。整段体验应像一趟完整旅程，而不是三个互不相关的场景演示。
