# 空间设计｜列车 Hub 与云海尽头

状态：空间拓扑为本任务的设计基线；列车最终外形、终点站主地标造型属于 PROPOSED，需总设计师批准后进入 Tripo 生产。

## 1. 设计原则

1. 列车是旅程中的共同空间，不是普通菜单页。
2. 玩家必须理解自己身处列车、即将去往哪里、如何进入下一站。
3. 车厢空间紧凑但有生活感；不要把一节车厢做成空旷大厅。
4. 终点站通过“列车停靠—站台—主建筑—观景路线—云海尽头”形成完整空间体验。
5. 三个世界的入口/出口接口统一，但各世界内部空间由各自 Owner 负责。
6. 所有比例先以玩家角色身高 H 为基准；实际编辑器单位由 A 在技术探针中测量后记录。

## 2. 列车 Hub：单节观景车厢

### 2.1 功能分区

`
┌──────────────────────────────────────────────┐
│              全景窗 / 云海视野                 │
│                                              │
│  [座椅区]       [中部活动空间]     [纪念物架]   │
│                                              │
│  [行李/灯具]    [旅程路线图墙]     [站点信息]   │
│                                              │
│  入站门 / 出生点                 离站门/过渡区  │
└──────────────────────────────────────────────┘
`

布局示意仅表达功能关系，不是最终尺寸图。

### 2.2 区域说明

**A. 入站门 / 出生区**
- 玩家进入 Hub 后能立刻看见车厢内部和一侧全景窗。
- 出生点前方保留至少 2H 的无障碍活动空间。
- 不把行李箱、椅子或灯具放在玩家出生路径上。
- 需要一个可识别的车门框和到站提示位置。

**B. 观景窗与座椅区**
- 一侧设置连续或分段的大窗户，让玩家看到云海和当前站点的远景。
- 座椅靠窗摆放，不阻塞主通道。
- 车厢灯光以暖色为主，窗外环境作为冷/暖变化的补光。
- 座椅主要是氛围资产，除非编辑器明确支持坐姿交互，否则不把“可坐下”列为 P0。

**C. 旅程路线图墙**
- 放在玩家进入车厢后容易看到的位置。
- 显示三个站点的顺序：书桌站 → 失重花园 → 云海尽头。
- 采用实体地图装置/站点灯点亮的视觉表达，不依赖复杂 UI。
- 首版可以是静态地图；如果逻辑交互可用，再增加当前站点高亮。

**D. 纪念物陈列架**
- 为书桌站的微缩地图/尺子小物、失重花园的漂浮种子预留展示格。
- 第一版可使用占位物或空格，不要求实现收藏数据库。
- 这是旅程记忆的视觉载体，不是复杂经营系统。

**E. 离站门 / 过渡区**
- 车厢另一端设置清楚的离站方向。
- 通过站点标牌、门灯或路线图提示下一站。
- 真实场景跳转方式按 A1/A3 技术探针确定。

### 2.3 比例建议

先测量当前玩家角色身高 H，之后按比例搭建：
- 主通道净宽：至少 2.5H。
- 车厢内部净高：约 2.8–3.2H。
- 门洞净高：至少 1.8H，宽度至少 1.1H。
- 座椅高度：约 0.5–0.6H。
- 座椅前方通行净距：至少 1.2H。
- 车厢内部总长度建议 10–14H，宽度 4–5H。

以上为设计比例建议，不是编辑器硬性单位；若角色碰撞体或摄像机视角要求不同，以实测结果调整。

## 3. 三世界连接拓扑

### 3.1 首选体验流程

`
起始车厢
   ↓
书桌站《桌面以下》
   ↓
返回列车 Hub / 下一站提示
   ↓
失重花园
   ↓
返回列车 Hub / 最后一站提示
   ↓
云海尽头
   ↓
终点观景台
`

### 3.2 统一接口

每个世界必须向 A 提供：
- Entry Anchor：进入该世界的出生点。
- Exit Anchor：离开该世界返回列车/下一站的位置。
- Entry Facing：玩家进入时面向方向。
- Safe Landing Area：安全落脚区。
- Anchor Screenshot：入口和出口在编辑器中的截图。
- Transition Method：实际使用的传送/场景连接方式。
- Fallback：连接功能不可用时的降级路线。

A 必须提供：
- TrainHub Entry。
- TrainHub Return。
- NextStop Trigger / Door。
- 当前站点显示方式。
- 完整旅程顺序和跳转测试记录。

### 3.3 连接方式优先级

1. 已实测可用的官方传送门/场景跳转组件。
2. 编辑器支持的场景/地图切换方式。
3. 可导入的独立区域模块，在同一项目中通过门/通道连接。
4. 最后降级为同一场景内的分区入口和遮挡过场。

不允许因为“希望无缝”而投入大量时间开发未验证的复杂机制。

## 4. 云海尽头：纯展示终点站

### 4.1 空间拓扑

`
                 [云海尽头 / 观景平台]
                           ▲
                           │
                 [高处云海步道]
                           ▲
                           │
       [中央车站大厅 / 主地标 / 钟楼]
                           ▲
                           │
       [终点站台 / 列车停靠 / 玩家出生点]
                           │
                    [铁路延伸至云雾]
`

### 4.2 区域 01：终点站台（Arrival Platform）

**功能：** 让玩家明确感受到列车抵达了终点。

构成：
- 一段可读的轨道/站台。
- 列车停靠位置。
- 站台顶棚或灯柱。
- 站牌/时刻表。
- 少量长椅、行李、栏杆。
- 一条清晰通往主建筑的路线。

验收：
- 玩家出生后能辨认列车和站台关系。
- 列车不能挡住前往主建筑的道路。
- 站台边缘有安全边界，不让玩家轻易掉出地图。
- 站台不能堆满无意义装饰。

### 4.3 区域 02：中央车站大厅 / 主地标

**功能：** 提供从远处就能识别的视觉中心。

主地标候选：
- A：复古钟楼 + 玻璃/金属站厅。
- B：大型穹顶站厅 + 悬挂时刻表。
- C：开放式拱廊 + 中央灯塔式信号装置。

当前推荐 A，但属于 PROPOSED。先做 2–3 个构图缩略图/概念对比，由总设计师批准后再制作 Tripo 核心资产。

模块：
- 主入口拱门。
- 立柱/拱券。
- 屋顶/玻璃穹顶。
- 时钟/站牌。
- 灯具。
- 台阶/坡道。
- 栏杆与边界。

### 4.4 区域 03：云海步道

**功能：** 把玩家从车站带到终点观景台。

要求：
- 路线有轻微弧度或高低变化，不做一条毫无变化的直线。
- 沿途设置 2–3 个视线窗口，让玩家逐渐看到更大的云海。
- 一侧可以有栏杆和灯柱，另一侧尽量保留开阔视野。
- 不设置需要复杂操作的机关。
- 路线长度以玩家步行约 30–60 秒为初始目标，最终通过试玩调整。

### 4.5 区域 04：终点观景台 / 铁路尽头

**功能：** 形成整个作品最后的视觉和情绪记忆点。

构成：
- 一个略高于步道的观景平台。
- 面向开阔云海的主视野。
- 铁轨或轨道痕迹在远处逐渐进入云雾。
- 远景可以用轮廓/灯光暗示书桌站与失重花园，不要求真实可达。
- 一个适合玩家停留、截图和观看的构图位置。

验收：
- 从观景台能看见云海的前/中/远景层次。
- 车站主地标仍然出现在回望视野中。
- 不能让雾效遮住所有建筑细节。
- 终点不是一块空地，必须有明确的“抵达”构图。

## 5. 终点站构图检查

必须交付以下四个机位：
1. Hero Wide：从站台看主建筑、列车和云海。
2. Mid Path：从步道看向观景台。
3. Final Vista：站在观景台看云海和远方。
4. Reverse View：从观景台回望车站和列车。

每个机位都检查前景/中景/远景：
- 前景：栏杆、站台边缘、灯柱、玩家。
- 中景：列车、站厅、钟楼/主地标。
- 远景：云海、远方浮岛、天空和光线。

## 6. 远景世界轮廓

允许在云海尽头出现前两个世界的抽象视觉符号：
- 书桌站：台灯的暖色光点、巨大书脊轮廓。
- 失重花园：悬浮花冠/温室的轮廓。

这些只能作为远景暗示，不能让玩家误以为还有第四个可玩世界，也不要在远景中直接贴入完整概念图。
