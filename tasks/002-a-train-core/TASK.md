# A-01｜列车公共空间、世界连接与云海尽头

## 1. 目标

A 负责建立一节有辨识度的列车公共空间，打通三个世界的入口/出口，并制作纯展示终点「云海尽头」。

最终体验：
- 玩家能理解列车是三个世界共同的旅程载体。
- 玩家能从列车进入书桌站和失重花园，并返回/继续旅程。
- 云海尽头有明确的抵达感、可漫游路线和值得停留的观景终点。
- 三个世界在体验上各自独立，但通过列车、声音和旅程线索保持统一。

## 2. A 的责任

1. 验证项目保存、恢复、Git、GLB/WPRE 交接。
2. 建立列车 Hub 和旅程路线图。
3. 与 B/C 定义世界入口、出口和连接约定。
4. 制作云海尽头展示世界。
5. 接入列车声音和统一旅程声音标识。
6. 持续集成 B/C 的成果并完成完整旅程验收。

A 不负责替 B/C 制作其世界，也不需要把终点站扩展成大型城市或完整模拟系统。

## 3. 设计意图

### 列车 Hub
列车应让玩家觉得这是一个可以返回的旅程空间，而不是菜单界面。它可以有窗景、座椅、路线图、少量旅程纪念物和清楚的下一站提示。具体布局由 A 自主探索。

### 世界连接
优先实现稳定、可复现的进入和返回体验。无缝切换不是目标本身；如果编辑器不支持，使用门、短过场或同场景分区等可靠方式。

### 云海尽头
这是旅程的最后一站，主要价值是空间、氛围和回望。需要有：
- 列车抵达/停靠的识别。
- 一个足够鲜明的主地标。
- 一条自然的观景漫游路线。
- 一个开阔、有层次的最终视野。
- 对前两个世界的轻微视觉呼应。

钟楼、穹顶、灯塔或其他建筑都只是候选，不要因为任务包写了某个例子就放弃更好的构图。

## 4. 自主探索空间

A 可以根据研究和编辑器实际能力自主决定：
- 车厢内部具体布局。
- 终点站主建筑形态。
- 场景模块如何拆分。
- 站点之间的具体过渡方式。
- 音频如何接入。
- 哪些资产用官方库、Blender 组合或总设计师生成的 Tripo 模型。

如果发现更好的设计，应先做小样或概念对比，说明玩家体验收益，再进入正式制作。

## 5. 非目标

- 真实列车驾驶模拟。
- 复杂轨道物理。
- 多节车厢经营系统。
- 终点站大型 NPC 城镇。
- 未验证的复杂无缝加载或动态演出系统。
- 为装饰数量牺牲主路线、构图和完成度。

## 6. 完成定义

- 项目可重新打开，交接方式有实测记录。
- 列车 Hub 可运行，入口、下一站和返回逻辑清楚。
- 三个世界接口有文档和实际验证。
- 云海尽头可从列车下车后自由探索至观景终点。
- 音频实际播放，来源和授权记录清楚。
- B/C 成果已在统一版本中验证。
- 有完整旅程录屏和可恢复版本。
