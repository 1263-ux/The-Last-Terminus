# TASK A｜列车公共空间、世界连接与云海尽头

## 0. 任务元信息

- Task ID：A-01
- Owner：成员 A
- Reviewer：总设计师；技术交接由 B 或 C 交叉验证
- Priority：P0
- Duration：一周冲刺中的持续工作流
- Depends On：项目仓库可访问；新版造世界 AI 编辑器可运行；总设计师提供视觉方向反馈
- Status：READY FOR DESIGN REVIEW
- Main Deliverables：项目交接报告、列车 Hub 白盒、World Interface Contract、终点站白盒与精修场景、集成版本、完整录屏

## 1. 唯一目标

交付一个可运行的公共列车空间和一个有视觉记忆点的终点站，并让书桌站、失重花园可以通过统一入口/出口协议接入。列车是旅程空间，不是菜单；终点站是纯展示世界，不追加复杂任务。

## 2. 产品与体验背景

项目不是三个互不相关的地图。玩家通过列车经历三个世界：
- 书桌站《桌面以下》：微观尺度、物件改造、环境解谜。
- 失重花园：空间方向、垂直探索、路线发现。
- 云海尽头：宏大景观、观景、旅程收束。

A 负责让玩家感受到“我一直在同一趟旅程中”，而不是在三个 Demo 之间被硬传送。统一感主要来自：
1. 同一列车的视觉识别。
2. 同一套车厢/站台材质语言。
3. 同一张旅程路线图。
4. 一致的到站/离站音频提示。
5. 明确的世界入口和返回位置。

列车起源、列车最终真相、云隙本体仍是开放设定。A 只制作可体验的表层，不得擅自写死世界观答案。

## 3. 任务拆分

### A0｜理解项目与组建 Agent 工作小组

1. 阅读 README、AGENTS、World Bible、Train Design 和本任务包。
2. 用 8–12 条 bullet 复述：本项目定位、三个世界职责、A 的边界、未确认设定、编辑器未知项。
3. 组织本任务的 Agent 小组，配置见 `AGENT-TEAM.md`。
4. 产出执行计划，标出哪些任务可并行、哪些必须等总设计师批准。
5. 不要立即开始精细模型生产。

交付：`reports/A0-understanding-and-plan.md`。

### A1｜项目、Git、GLB/WPRE 技术探针

按 `EDITOR-PLAYBOOK.md` 执行，必须实测：
- 当前编辑器版本、系统环境、项目创建方式。
- 本地项目实际目录、保存、关闭、重新打开。
- Git 初始化、提交、克隆、另一成员拉取后打开。
- GLB 导入：层级、材质、贴图、缩放、朝向、碰撞。
- WPRE 导入：层级、材质、贴图、碰撞、交互、外部依赖。
- 项目/场景/资产跨成员交接。
- 编辑器版本差异与二进制冲突。

交付：
- `reports/A1-project-and-git-probe.md`
- `reports/A1-glb-wpre-import-matrix.csv`
- 可复现的最小测试项目/资产
- 录屏和截图

### A2｜公共列车 Hub 白盒

先搭空间，不做精细美术。按 `SPATIAL-DESIGN.md` 完成：
- 一个紧凑车厢/观景车厢。
- 一个入口/到站门区。
- 一个旅程路线图墙。
- 一个纪念物陈列位置（首版可以空置或放占位物）。
- 一个离站/下一站入口。
- 玩家出生点、回退点和可复现的出口定位方式。

交付：
- 可重新打开的 Hub 白盒。
- 俯视布局图。
- 玩家出生点到出口的连续录屏。
- 场景层级截图。
- 主要空间比例记录（以角色身高 H 为参照，不凭空写编辑器米制单位）。

### A3｜World Interface Contract 与连接探针

定义三个世界统一接口：
- 每个世界一个 Entry Anchor。
- 每个世界一个 Exit Anchor。
- 入口朝向、地面高度、安全落脚区、出生保护范围。
- 返回列车的方式。
- 世界完成后进入下一站的触发方式。

优先验证：列车 Hub → 书桌站 → Hub → 失重花园 → Hub → 云海尽头。

如果新版编辑器不支持跨项目场景切换，按以下顺序降级：
1. 使用已验证的传送门/场景跳转组件。
2. 将各世界做成可导入的独立区域/模块，在同一主项目中拼接。
3. 若完整场景无法导入，则以 WPRE/GLB 交付场景模块，交互在主项目中重建。
4. 最低限度使用同一场景内的分区入口和遮挡过场。

禁止用没有证据的“应该可以”作为连接方案。

交付：`world-interface/WORLD-INTERFACE-CONTRACT.md`、`reports/A3-transition-probe.md`、至少一次真实连接录屏。

### A4｜云海尽头白盒

按 `SPATIAL-DESIGN.md` 完成四段空间：
1. 终点站台 / 列车停靠区。
2. 车站主建筑 / 主要地标。
3. 通往高处的云海步道。
4. 终点观景台 / 铁路尽头。

要求：
- 玩家出生后 5–10 秒内能看到主地标或清楚方向。
- 玩家从列车下车后有一条自然、可读的观景路线。
- 终点观景台必须有明显视野奖励。
- 远处能用轮廓或灯光暗示前两个世界，但不要把它们做成假贴图或强行拼接的浮岛。
- 纯展示不等于无路线：必须让玩家有一段可探索、可停留的空间。

交付：全景、俯视布局、入口至观景台连续录屏。

### A5｜关键美术资产接收与场景精修

1. 根据 `ASSET-BRIEFS.md` 向总设计师提交 Tripo 资产需求。
2. 总设计师完成 Tripo 生成后，A 接收 GLB。
3. 使用 Blender 检查比例、原点、法线、UV、材质、贴图和网格。
4. 导入新版造世界 AI 编辑器，检查材质/贴图/缩放/碰撞/层级。
5. 核心资产通过后，再加入普通模块、栏杆、灯具、站牌和装饰。
6. 不得用装饰密度掩盖空间构图问题。

交付：资产导入报告、远/中/近景截图、精修场景版本。

### A6｜音频接入与最终集成

- 统一列车运行声、汽笛/到站声、车门/制动声。
- 列车 Hub 有独立但克制的环境底噪。
- 终点站有开阔风声、空间氛围和终点音乐。
- 书桌站、失重花园保留各自环境声，不由 A 擅自替换。
- 如果编辑器没有独立音频总线/淡入淡出能力，使用当前版本支持的最简单可靠方式，不编造混音功能。
- 收集 B/C 的 World Package，按接口集成。
- 完成完整旅程从头到尾的运行检查。

交付：集成版本、音频资产登记、完整旅程连续录屏、最终问题清单。

## 4. A 的工作优先级

P0：
- 项目保存/恢复、Git/WPRE/GLB 交接验证。
- 列车 Hub 白盒。
- World Interface Contract。
- 三世界连接至少一条完整路径。
- 终点站主路线和观景点。
- 最终集成可运行。

P1：
- 列车外观精修。
- 终点站主建筑精修。
- 路线图和纪念物陈列。
- 统一音频和到站演出。

P2：
- 多节车厢。
- 复杂列车机械动画。
- NPC、售票、商店、乘客日程。
- 复杂收藏系统和动态天气。

## 5. 设计批准点

以下内容必须先由总设计师批准：
- 列车最终外形和色彩方向。
- 终点站主地标造型。
- Tripo 关键模型需求卡。
- 列车与三个世界的尺度关系。
- 会改变世界入口/出口或玩家路线的设计修改。

## 6. 任务完成定义

A 不能仅以“模型导入成功”或“场景搭出来”作为完成。必须满足：
- Hub 可重新打开并正常运行。
- 三个世界接口明确且可复现。
- 终点站玩家能从列车下车，沿路线抵达观景台。
- 核心资产没有严重材质、比例、碰撞或缺失依赖问题。
- 音频实际播放并通过试玩检查。
- B/C 的交付已在主集成版本中验证。
- 有完整旅程录屏和可恢复版本。
