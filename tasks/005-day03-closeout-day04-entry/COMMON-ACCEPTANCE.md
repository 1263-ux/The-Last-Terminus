## 0. 状态标签

每项只能使用：
- PASS：按指定运行模式真实复测通过，证据可复现。
- FAIL：真实复测失败。
- NOT TESTED：尚未执行，不能推断。
- INCONCLUSIVE：执行过，但证据不足或测试中断。
- WAIVED：总设计师明确书面豁免，并记录风险。

“代码存在”“API 返回成功”“编辑器视口截图”“Agent 自评”都不能自动等于玩家体验 PASS。

## 2. B｜书桌站玩家闭环验收

### 2.1 当前基线

B 最新提交 a53c627 已证明玩家视角渲染问题源于可见角度预算。当前实测参考：
- camY = 79.587
- camZ = 85.3
- pitch = 18° 向下
- FOV = 45°，半 FOV = 22.5°
- 可见条件：topY <= 79.587 + (z - 85.3) * 0.0787
- B 的摆位建议额外留 20% 余量。

这组数值只适用于当前 B 的相机/工程基线。相机或出生点改变后必须重新测量，不得把公式不加检查地复制到 A/C。

### 2.2 玩家闭环

| ID | 步骤 | PASS 标准 |
|---|---|---|
| B-01 | 出生与目标 | 玩家出生后能看见书谷、REST 尺子和对岸小镇目标；主要物件没有顶出画面 |
| B-02 | 理解交互 | 玩家能从视觉线索理解尺子与通路改变有关；不要求复杂文字说明 |
| B-03 | 主动触发 | 必须由玩家进入/使用绑定交互触发；不能出生自动激活 |
| B-04 | 状态切换 | REST 隐藏，RAMP 六段全部显示；切换发生在玩家视角中且清晰可见 |
| B-05 | 门禁规则 | 未解锁前进入门禁区会被规则退回安全点；已解锁后允许通过；不能依赖实体墙阻挡 |
| B-06 | 实际通行 | 玩家从坡道入口连续移动到小镇，不可用传送截图代替走通 |
| B-07 | 到达反馈 | 到达小镇后至少有一项可感知反馈：灯光、声音、场景状态或明确提示 |
| B-08 | 恢复 | 失败/误触后可回到安全位置，重新尝试，不软锁 |
| B-09 | 复玩 | 关闭并重新打开工程后，场景和脚本绑定仍在；状态初始值正确 |

### 2.3 不通过的情况

以下都不算完整闭环：
- 只看到逻辑变量变成 true。
- REST/RAMP 两种状态预先同时摆在不同位置，玩家没有触发过程。
- 玩家出生即解锁。
- 只切换 RAMP_1，RAMP_2..6 未显示。
- 只用节点定向截图证明玩家视角可见。
- 玩家无法真正走到小镇。
- 以实体墙碰撞作为唯一门禁。

### 2.4 B 的最小验收录屏

一镜到底，建议 45–90 秒：
1. 正常出生。
2. 看见 REST 和目标小镇。
3. 靠近并主动触发。
4. 镜头内看到 REST → RAMP 状态切换。
5. 显示六段坡道。
6. 沿坡道连续走到小镇。
7. 出现到达反馈。
8. 展示返回/失败恢复方式。

## 3. C｜失重花园体验验收

### 3.1 固定范围

保持 Plan C，不扩图：
入口浮岛 → 断桥/路线线索 → 根系路线 → 倒悬温室屋顶 → 花冠观景点。

不增加新岛屿、新谜题系统或真实任意方向重力。

### 3.2 观景点

| ID | 验收项 | PASS 标准 |
|---|---|---|
| C-01 | 默认到达视角 | 玩家抵达花冠观景点时，下一目标/地平线奖励在默认视角可见 |
| C-02 | 正常 Look-back | 玩家使用正常可用的 Look 输入后，3 秒内能识别来时路线 |
| C-03 | 无强制镜头 | 不得使用脚本强制 yaw、镜头接管或自动转镜头伪造通过 |
| C-04 | 无自由 Look 时降级 | 如果 GUI 实测无可用自由 Look，提供物理回转平台/短回转路径，玩家自行转身后看见来路 |

### 3.3 独立路线盲测

至少两名未参与设计的试玩者；测试前不能口头告诉路线。

记录：
- 从出生到首次注意到温室的时间。
- 从断桥到发现根系路线的时间。
- 错误转向次数。
- 坠落次数。
- 是否主动请求帮助。
- 是否完成抵达温室/观景点。
- 玩家能否解释为什么根系是可通行路线。

如果当前无法找到两名测试者，标记 NOT TESTED，另附内部自测，但不得把内部自测计为盲测通过。

### 3.4 45 秒 Backup Cue

| ID | 验收项 | PASS 标准 |
|---|---|---|
| C-05 | 计时 | 从指定入口进入开始计时，真实等待 45 秒，不用 3 秒探针替代 |
| C-06 | 一次性 | 同一次游玩最多触发一次；重复进入/抖动不会重复播放 |
| C-07 | 提示内容 | 光线/点光提示确实指向根系或正确路线；若有声音，声音实际可听 |
| C-08 | 无干扰 | 提示不会遮挡玩家或制造错误路线暗示 |
| C-09 | 重开 | 关闭并重新打开项目后重新测试，计时与去抖行为正常 |

### 3.5 坠落恢复

- 从每个主要失败区域实际坠落。
- 确认玩家回到入口/检查点并能继续。
- 不能只用 Teleport 命令结果当作落地/可走证据。
- 恢复后确认不会重复触发 Backup Cue 或卡在触发区。

### 3.6 接口交付

必须提交运行时实测：
- Entry position (x,y,z)
- Entry spawn yaw
- Exit position (x,y,z)
- Safe zone 范围
- Return target
- 坐标单位/坐标系
- 编辑器版本与项目版本

Three.js 作者源坐标不可直接作为运行时世界坐标；注意已验证的 GLB X 镜像问题。

## 5. Day 4 入场 Go / No-Go

### GO：允许进入单个代表性 Hero Asset 验证

必须同时满足：
- [ ] B 的玩家视角可见性已有结论（当前 B2 已 PASS；若工程/相机变更则重测）。
- [ ] B 的 REST → RAMP 主动交互、六段切换和连续通行闭环通过，或总设计师明确批准有证据的降级方案。
- [ ] C 的默认观景视角和 Look-back/物理回转方案通过真实 GUI 测试。
- [ ] C 的两名独立盲测已通过，或总设计师书面批准“先进入单资产样板、盲测作为并行阻塞项”的例外。
- [ ] A 的 GLB 导入约束和资产清单稳定。
- [ ] 至少一个 A/B/C 间的 GLB/WPRE 跨成员导入实际成功。
- [ ] 一个真实 Tripo 导出完成导入和材质检查。

### NO-GO：继续局部修订

出现以下任一项：
- B 核心交互由逻辑变量触发但玩家看不到。
- B 无法实际走到小镇。
- C 观景点仍无法识别目标或来路。
- 关键 WPRE/GLB 依赖丢失且无降级方式。
- 项目无法保存、重新打开或恢复。

### 允许的例外

若只有真人盲测人员暂不可用，可以由总设计师批准先进行“单个代表性资产技术验证”，但不得宣称 C-Gate 通过，也不得批量生产。

## 6. 通用证据包

每位成员提交：
- REVISION.md：每个 ID 标 PASS/FAIL/NOT TESTED/INCONCLUSIVE。

- BLOCKERS.md：阻塞、复现、影响、降级。
- 实际编辑器截图：远景、中景、近景。
- 连续录屏：从出生开始，玩法必须录到闭环。
- Git Commit SHA。
- 编辑器版本、项目 ID（敏感 ID 可脱敏）。
- 已知偏差和下一步。
