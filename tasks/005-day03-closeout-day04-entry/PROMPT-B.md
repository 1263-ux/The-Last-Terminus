## 4. B2｜完成玩家主动交互闭环（最高优先级）

目标体验：

玩家出生 → 看见书谷缺口、REST 尺子和小镇 → 理解尺子可改造 → 主动触发交互 → REST 隐藏/RAMP 六段出现 → 状态门禁放行 → 玩家连续走过新路线 → 到达铅笔盒小镇 → 获得反馈。

### 步骤 1：入口可读性

1. 从正常出生点启动真实玩家视角。
2. 确认书谷、REST 尺子和小镇目标都可辨认。
3. 玩家 5 秒内能知道主要目标方向。
4. 如果尺子用途不明显，增加一个低成本视觉提示：支点、桥端落点、刻度对齐或一处环境标记。不要堆长篇文字。
5. 远景/中景/近景各留一张截图。

### 步骤 2：主动交互

1. 向 C 请求已验证的 GUI Trigger + Lua 绑定步骤。
2. 向 A 请求最新的参数化 C4 门禁示例。
3. 在 Desk 工程里由 B 本人通过 GUI 绑定脚本。
4. 正常出生时必须保持 activated=false。
5. 玩家必须走到明确的交互位置并主动触发。
6. 不得把出生点放在 unlock 区里，不得让 Update 逻辑自动解锁。
7. 交互触发要有即时反馈（短音效、灯光、轻微动效或明确状态变化，至少一个）。

### 步骤 3：REST → RAMP 六段替换

1. 触发前：REST 可见，RAMP_1..6 不可见。
2. 玩家交互后：REST 隐藏。
3. RAMP_1..6 六段全部显示。
4. 逐个检查六段的方向、连接、间距、落脚区域。
5. 不能只显示 RAMP_1。
6. 状态切换必须在玩家相机中可见。
7. 保存、关闭、重新打开后，脚本绑定和节点结构仍正确。

如果六段有共同父节点，可先确认父节点是否只包含这六段，再切换父节点；如果不是，逐个切换。不要未经检查就隐藏/显示整个大场景父节点。

### 步骤 4：规则门禁

当前玩家是脚本驱动的运动学 NetworkActor，普通场景 Collider 不能可靠阻挡水平移动。

所以：
- 不再制作实体墙来挡玩家。
- 不依赖“玩家撞上墙”作为锁定反馈。
- 使用一个可见的状态门禁：未激活时，进入门禁区域后返回安全点或触发明确的未解锁反馈；激活后放行。
- 返回点必须使用 B 当前工程实测坐标，不能使用 A 脚本中的 x=119.74/z=88 等测试坐标。
- 门禁区不得与正常出生点重叠。
- 触发器要有冷却/去抖，防止连续传送或重复执行。

### 步骤 5：连续通行

1. 重新启动真实玩家运行。
2. 从坡道入口开始。
3. 使用连续玩家移动走过六段 RAMP。
4. 不使用 Teleport 截图代替真实通行。
5. 不使用编辑器定向截图代替玩家视角。
6. 记录是否掉落、卡住、偏离路线、触发重复传送。
7. 到达铅笔盒小镇入口。

### 步骤 6：小镇到达反馈

至少实现一个稳定反馈：
- 小镇暖窗点亮；
- 小镇入口灯亮起；
- 一段短环境声/提示音（先确认音频真实可听）；
- 一个标识/旗帜/门的状态变化。

不要为了反馈新建复杂 NPC 系统。

### 步骤 7：恢复与重开

- 未解锁误入门禁区：回安全点。
- 触发过程中重复进入：不重复切换/不连续传送。
- 完成后可以返回列车。
- 关闭并重新打开工程后，场景、脚本绑定和节点仍存在。
- 重新试玩一次完整流程。
