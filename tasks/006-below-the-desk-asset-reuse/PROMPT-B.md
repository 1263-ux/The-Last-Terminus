## 5. 实现《断裂的书谷》主谜题

核心流程：
玩家出生 → 看见书谷和小镇目标 → 观察尺子与两个支点 → 理解尺子用途 → 主动进入整理/交互 → 合法预览/确认 → REST 隐藏、完整桥体出现 → 玩家连续走过桥 → 小镇入口灯亮/环境回应 → 地图或日志记录第一条道路。

### 交互状态

尽可能映射以下状态：
- Exploration：探索和移动；
- Inspecting：观察尺子/支点，显示简短用途提示；
- Planning：进入整理/摆放；
- Previewing：显示合法/非法摆放反馈；
- Committing：确认后切换 REST/RAMP；
- Recovering：撤销、重置或回安全点。

### 编辑器能力降级顺序

原始设计要求拖动尺子到两个锚点、合法/非法预览和确认。当前编辑器不能依赖普通 Collider 阻挡运动学玩家，也不能假定支持任意物理摆放。按以下顺序验证：
1. 若 GUI 支持拖动和锚点吸附，优先实现拖动、预览、确认。
2. 若自由拖动不稳定，使用明确的交互区 + 预设锚点吸附，玩家主动选择/确认落位。
3. 若锚点 UI 不可用，使用显式交互按钮/触发器，玩家主动确认后播放落位表现并切换状态。
4. 不得出生自动激活；不得用实体墙作为唯一门禁；不得假称物理沙盒已实现。

桥体结构可以是一个 GLB root（内部多个 mesh）或多个 child/root。**验收完整桥体，不强制拆成 6 个独立坡道节点。** 所有桥体 mesh 必须一起正确显示，不能只显示一部分。

### 门禁和实际通行

- 未激活时进入门禁区，使用 Trigger/Lua 规则返回安全点并给出明确反馈。
- 激活后放行。
- 不能依赖普通 Collider 挡住玩家。
- 激活后必须真实测试玩家是否能连续沿桥面走到对岸。
- 如果桥面不能承载玩家，先提交最小复现和降级提案；不得用 Teleport 截图冒充连续通行。

### 主解法与替代解法

- P0：尺子桥主解法完整。
- 回形针与绳索是替代解法候选；若绳索碰撞和角色通行不稳定，降级为固定捷径/展示路线，不阻塞主切片。
- 不为“多解”数量堆砌系统。

## 6. 5–8 分钟垂直切片

目标来自 GDD v0.2 和 VERTICAL_SLICE_SPEC v0.2。不要用等待或重复收集填充时长。

建议流程：
1. 入口与尺度建立：看见书谷、尺子和小镇目标。
2. 自主探索近侧书本平台，观察书页、书脊、支点或一处环境细节。
3. 靠近尺子，触发 Inspecting 提示，理解它可用于跨越。
4. 进入整理/交互，完成合法预览或锚点吸附。
5. 确认后观察 REST → 完整桥体变化。
6. 连续走过桥，记录真实通行耗时和卡点。
7. 到达小镇入口，触发暖窗/入口灯/居民预设动作中的至少一项。
8. 更新地图/探险日志；若 UI 不支持，使用明确环境状态反馈并提交降级说明。
9. 返回安全点或列车，确保没有软锁。

至少找一名未参与设计者完成无口头讲解试玩，记录实际时长、目标理解、物件发现、整理模式理解、误操作、过桥卡点、继续探索意愿和最粗糙资产。目标 5–8 分钟，偏差要如实解释。

## 7. 视觉验收

遵循 Art Bible：
- 书本要体现纸张纤维、页边厚度、封面/书脊布料，不要像岩石峡谷。
- 尺子刻度清楚、支点和落脚关系可信。
- 铅笔盒小镇有深青绿外壳/拉链/隔层、布棚和暖窗，不要做成普通中世纪村庄。
- 台灯是“太阳”式远景锚点，暖光不能过曝。
- 远景/中景/近景均从玩家视角检查；不能只用编辑器自由视角。
- 资产材质和路线可读性优先于装饰数量。
