# TASK ACCEPTANCE｜资产复用与 A/B/C 当前阶段 Gate

## 0. 证据状态

统一使用：
- PASS：目标编辑器/真实玩家/真人操作按要求通过。
- FAIL：真实复测失败。
- NOT TESTED：没有执行。
- INCONCLUSIVE：执行过但证据不足。
- WAIVED：总设计师书面豁免。

Blender 独立评审 ACCEPTED 不等于造世界编辑器导入 PASS。Agent 自评不等于总设计师 Gate。

## 1. A｜公共技术与集成

| ID | 验收项 | PASS 标准 |
|---|---|---|
| A-01 | C4 状态脚本 | 支持一个完整 GLB 根节点，或明确配置的多个子节点；不再硬编码只切换 RAMP_1；参数包含 REST、Bridge/RAMP root 或节点列表、交互区、门禁区、返回点和 yaw |
| A-02 | 初始状态 | 正常出生为 REST 可见、Bridge/RAMP 隐藏、activated=false；出生位置不得落在自动解锁区 |
| A-03 | 主动激活 | 玩家真实触发交互后 REST 隐藏、完整 Bridge/RAMP 表示出现；同一绑定实例状态一致 |
| A-04 | 门禁与恢复 | 未激活越界能回到安全点并给反馈；激活后放行；重复触发有冷却/去抖；不依赖实体墙阻挡运动学玩家 |
| A-05 | GLB 技术交接 | 对 B 的资产包提供可复用导入步骤；记录尺寸、朝向、X 镜像、材质/贴图和目标编辑器运行表现 |
| A-06 | WPRE/GLB 跨成员 | 由接收方 B 或 C 在自己的工程导入、保存、重开并运行；不能用 A 同机测试代替 |
| A-07 | World Interface Contract | Desk/Garden Entry、Exit、spawn_yaw、安全区、return target 为运行时实测值；没有数据就标 WAITING FOR OWNER |
| A-08 | 技术报告 | 115m 连续行走仍 INCONCLUSIVE，除非真实连续复测；音频 API 成功与人耳听到分开记录 |

### A 的特别要求

- 当前 `tools/c4_complete_gate.js` 是技术示例，不是 B 的最终脚本。原示例坐标、UNLOCK_Z/GATE_Z 和单个 RAMP_1 不得直接复制到 B 工程。
- 如果 B 导入 `ruler-bridge-full-v01.glb` 后得到一个根节点和六个 mesh children，允许切换根节点；若导入后拆成多个 root，则建立父节点或逐一切换。**不要求把 6 个 mesh 强行当成 6 段坡道。**
- B 的交互入口应使用 C 已验证的 GUI Trigger + Lua 绑定路线；如当前版本不支持，提出有证据的降级方案，不要把 CLI 位置轮询伪装成 GUI 交互。

## 2. B｜书桌站资产导入与可玩闭环

### B-01 资产包接收与登记

- [ ] B 收到 `BelowTheDesk-造世界编辑器资产交接包-v1.0.zip`。
- [ ] SHA-256 与 `ASSET-IMPORT-MANIFEST.md` 一致。
- [ ] 保留原始 GLB，不直接覆盖。
- [ ] 把确认采用的 GLB 和清单提交到 `shared-assets/desk-world/below-the-desk-kit-v1/`（若当前仓库容量/政策不允许，先提交清单和可复现交接方式）。

### B-02 目标编辑器导入烟雾测试

优先顺序：
1. `town-row-v02.glb`（无纹理，先验证多部件层级和 24m 尺寸）
2. `shopfront-v02.glb`（无纹理，验证单体模块）
3. `ruler-bridge-full-v01.glb`（核心资产，重点验证嵌入 PNG 刻度）
4. `desk-lamp-v01.glb`（灯具模型；光照在编辑器另行配置）
5. `cup-harbor-v03.glb`（可选远景；纹理解码未验证）
6. `case3-assembly-reference-v02.glb`（只作为组合参考，不直接替换最终关卡）

每个采用资产必须验证：
- SHA、文件大小；
- 导入后层级/部件名称；
- 单位、比例、朝向、原点；
- X 镜像和旋转；
- 材质/嵌入贴图；
- 玩家相机可见；
- 保存、关闭、重新打开；
- 目标运行时是否稳定。

### B-03 玩家相机与摆位

- 当前 B 相机基线（仅适用于未改相机的当前工程）：camY≈79.587、camZ≈85.3、pitch≈18° 向下、FOV≈45°。
- 可见性预算：`topY <= 79.587 + (z - 85.3) * 0.0787`，额外留余量。
- 如果出生点、相机、FOV 改动，必须重新实测。
- 不得只用编辑器自由视角或节点定向截图验收。
- 大型 24m town-row 应先在远/中/近景验证，再决定是否缩放或拆分；不要未经记录地随意缩放。

### B-04 尺子桥状态切换

当前资产有两种合理结构：
- 单个 GLB root（内部含多个 mesh children）；
- 导入器拆成多个独立节点。

验收按**完整桥体**而不是固定节点数量：
- 激活前：REST 尺子可见，完整桥体隐藏。
- 玩家主动交互后：REST 隐藏，完整桥体所有组成部分出现。
- 刻度、数字、支架、金属箍均显示正确。
- 不能只显示一段，也不能出现部分 mesh 遗漏。
- 如果纹理不解码，标 FAIL，先查贴图容器/材质路径，不得用纯色占位冒充原资产通过。

### B-05 核心玩法闭环

一镜到底真实玩家运行，目标 45–90 秒：
1. 正常出生，看到书谷、静止尺子和小镇目标。
2. 玩家理解尺子与通路有关。
3. 玩家主动触发交互（不是出生自动激活）。
4. 玩家相机内看到 REST → 完整桥体状态切换。
5. 玩家沿新路线连续走过桥/坡道。
6. 到达铅笔盒小镇，出现至少一个反馈（暖窗、入口灯、声音或场景状态）。
7. 返回/失败恢复有效。
8. 保存、关闭、重新打开后再走一次。

注意：当前玩家是运动学控制，普通 Collider 不能被当成物理墙。门禁用规则/Trigger/Teleport 设计，但**桥面是否能支撑玩家、玩家是否能实际走到对岸**必须真实运行测试。

### B Gate 通过条件

- [ ] 资产导入矩阵中的核心资产 PASS。
- [ ] 玩家视角看见 REST、桥体和小镇。
- [ ] 玩家主动交互，非自动触发。
- [ ] 完整桥体切换，无 mesh 遗漏。
- [ ] 一镜到底连续通行到小镇。
- [ ] 到达反馈与失败恢复通过。
- [ ] 重开后场景和脚本绑定保留。

## 3. C｜失重花园体验收尾

当前已通过的技术证据（以最新 `reports/day-03/C/REVISION.md` 为准）：
- Plan C 全程连续玩家移动实走（入口→根系下坡→温室屋顶→上行台阶→U 形回转→观景台）有证据。

- Runtime restart 后 cue 状态归零、再次触发封顶、坠落复位仍工作已有证据。

这些 PASS 不代表 Garden Gate 全部通过。当前剩余重点：

| ID | 任务 | PASS 标准 |
|---|---|---|
| C-01 | 清理重复场景实例 | 清除重复 garden-whitebox / 重叠云垫 / 重复 Trigger；单一运行场景只保留一套正式绑定 |
| C-02 | 清理后路线复测 | 全新 runtime，从入口连续走到观景台，路线不被残留实例挡住，无重复复位 |

| C-05 | 无自由 Look 降级 | 如果 GUI 确认没有可用自由 Look，设计物理回转平台/短回转路线，玩家自己转身看见来路 |

| C-08 | Entry/Exit | 运行时 Entry/Exit、spawn_yaw、安全区、return target 记录完整 |
| C-09 | 交接 | 把 C 的 GUI/盲测/运行证据与未决问题更新到报告 |

如果没有真人测试者，C-06 必须 NOT TESTED，不得由 Agent dry run 代替。

### 例外

若 C 的两人盲测人员暂不可用，总设计师可书面批准先做**一个代表性资产样板**；不得把 C Gate 标为 PASS，也不得进入批量美术生产。

### NO-GO

- 核心尺子桥贴图黑屏/部件丢失；
- B 只有逻辑状态变化，没有连续玩家通行；
- C 场景重复实例仍污染 Trigger/计时/视线；
- 项目保存重开后丢失脚本/资产；
- 没有可复现的跨成员资产交接。
